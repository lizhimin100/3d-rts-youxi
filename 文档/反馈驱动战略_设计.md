## 3.1 用户已确认的规格（不得修改）

> 以下四条是用户原话确认的口径。实现时**逐字**照做；若发现与代码现状冲突，
> 只允许报告冲突，不允许"顺手优化"数值或公式。

| # | 项 | 【用户已确认】规格 |
|---|---|---|
| C1 | 成本口径 | **只用金 + 木，不含人口。** |
| C2 | 快速被消灭 | **理论存活 = 波次成本 ÷ 过去 60 秒平均收入；实际存活 ÷ 理论存活 < 0.5 → 判定为"快速"**（阈值后续可调，但公式与口径本轮锁死）。 |
| C3 | 攒大波倍率 | **相对【上一次波次实际派出兵力】的 2.5 倍（选项 b）。** |
| C4 | 攒大波的依赖 | **必须先有"波次记录表"才能取到上次派出兵力。** |

补充说明（只解释，不改口径）：

- C1 的"成本"= Σ(单位 `gold_cost` + `wood_cost`)，按实际派出编制逐兵种求和；
  农民、人口、建造时间**都不计入**。
- C2 的"过去 60 秒平均收入"取**该阵营自己的**资源入库速度（金+木，按价值直接相加，
  不做金木换算——因为 C1 的成本也是直接相加）。实现上建议复用 bench 已有的
  `gold_income / wood_income` 采样口径（每 0.25 s 取正向跳变），窗口 60 s 滚动。
- C2 的"实际存活"= 从**出发时刻**到该波最后一名成员的**死亡或返回时刻**（取较早者）。
  若全员返回，实际存活 = 返回时刻 − 出发时刻。
- C3 的"兵力"= 派出的**单位数**（不是成本、不是战力值）；"上一次波次"若不存在（首波），
  则退化为"当前可派的全部战斗单位"。
- **C4 的"当前可派的全部战斗单位"定义（2026-11-02 明确）**：= 所有 `idle` 且不在
  巡逻 / 回防 / 建造任务中的战斗单位。**正在训练的、正在别的任务中的不算。**
  判据：`u.is_idle_like()`（`order == NONE`）为真，且该单位不在 `"patrol"` / `"defend"` /
  `"build"` 任一命令组里。这条定义同时约束 C3 的首波退化与 T9 的"全部战斗单位"。

## 3.2 已定死（2026-11-02 用户确认，**已定，不再变更**）

> 每项都给：**定死值** / 可调范围 / 影响面。下表"备选"与"不确认的后果"两列保留，只作历史记录（记录当时为什么这么定），**不再作为待决项**。

| # | 项 | 建议默认 | 可调范围 | 影响面 |
|---|---|---|---|---|
| P1 | "效果好"的判定：投入产出比（敌损成本 / 我投成本）阈值 | **≥ 0.9** | 0.7 ~ 1.2 | 定太高 → 永远判"一般"，攒大波永不触发；定太低 → 送兵也算好，越打越亏。用户原话："哪怕都是 1000，但进攻在敌人那打，战略空间和时间上还赚了，差 100 左右也不错"——0.9 是从这句推的。|
| P2 | 净交换比（敌损成本 / 我损成本）是否设下限 | **不设，仅记录** | 0 ~ 0.8（若设） | 设了下限会把"用亏损换空间/换时间"判死（比如拆掉对面一座关键兵营，己方死一半兵）；用户口径里"战略空间和时间上还赚了"正是这种情况。 |
| P3 | 连续几次"快速被消灭"才触发攒大波 | **3 次** | 2 ~ 5 | 太小 → 一亏就龟缩，永远在攒；太大 → 一直被小股消耗，攒不起来。**中间只要出现一次"效果好"就重置计数**（用户第一段提过"三次"；2026-11-02 已确认）。 |
| P4 | 攒大波时，小股骚扰是否走独立资金池 | **独立**：日常预算保留 ≥150 金才出小股；攒兵预算满 2.5 倍才放行 | 独立 / 不独立 | 不独立 → 边攒边被小股吃掉，永远到不了 2.5 倍（本轮 bench 的"114 次拒击"就是攒不起来的另一种形态）。 |
| P5 | 攒大波是否设上限 | **设上限 = 2.5 倍 × 2 = 5 倍封顶** | 3 ~ 8 倍 | 无上限 → "越攒越大，永远不出门"（和现在的死锁同构，只是换了个理由）。 |
| P6 | FFA 防坐大：同一目标连续 N 波效果递减 → 强制换目标 | **N=2**，判据：投入产出比从 ≥1.0 掉到 <0.8 | 1 ~ 3 波 | 不换 → 两家互耗、第三家坐大（本图是 4 队 3 阵营，队2/队3 不结盟，风险真实存在）。 |

## 3.3 策略状态机（转移表）

状态集：**试探 → 加强 → 攒大波 → 换目标 → 升科技换兵种**（五个，不含终态；对局结束由 `Game.phase` 截断）。

所有指令**必须**走 `_sched`（`命令调度.gd`），再由控制权过滤；本设计不新增下令通道。

| # | 当前状态 | 触发条件 | 下一状态 | 发出指令（`_sched` 入口） | 依赖的观测 |
|---|---|---|---|---|---|
| T1 | 试探 | 判定 = **达成 / 好** | 加强 | 无（本 tick 不加派） | 波次记录表：verdict + goal |
| T2 | 试探 | 判定 = **差**，连续差 < 3 | 换目标（出口 2） | 无（等 T12 选目标） | 战争记录：verdict、连续差计数 |
| T3 | 试探 | 判定 = **差**，连续差 ≥ 3 | 攒大波 | `_sched.move(留守单位, 基地内圈, "bank")` | 连续差计数（B5） |
| T4 | 试探 | 判定 = **一般** | 换目标（出口 1） | 无（等 T12 选目标） | verdict |
| T5 | 试探/加强 | 敌方无可达目标 | **换目标（T12）** | 无 | `_has_target()` |
| T6 | 加强 | 判定 = **达成 / 好** | 加强（同目标，全军） | `_sched.attack_move(units, 同一目标, "press")` | verdict |
| T7 | 加强 | 判定 = **一般** | 换目标（出口 1） | 无 | verdict |
| T8 | 加强 | 判定 = **差** | 攒大波（连续差 ≥3）或换目标 | `_sched.move(存活单位, 基地内圈, "regroup")` | 连续差计数 |
| T9 | 攒大波 | 兵力 ≥ **2.5 × 上次派出**（P5 封顶 5×），且目标有效 | 加强（打出去） | `_sched.attack_move(全部战斗单位, 目标, "wave_big")` | 上次派出兵力 / 当前集结 |
| T10 | 攒大波 | 基地被压（`base_threat ≥ 1`） | 试探（取消攒兵，先回防） | `_sched.attack_move(units, 基地, "defend")` | `metrics.base_threat` |
| T11a | 攒大波 | ≥90 s 未到 2.5×，但成本仍在增长 | 攒大波（继续） | 无 | 30 s 成本增量 |
| T11b | 攒大波 | ≥90 s 且成本停止增长 | 升科技换兵种 | `_sanity_research()` | 30 s 成本增量 |
| T12 | 换目标 | 选出新目标（含 goal 评分） | 试探 | `_sched.attack_move(units, 新目标, "probe")` | 0.4 距离 + 0.4 威胁 |
| T12b | 换目标 | 10 s 内选不出 | 试探 | 无 | 目标候选为空 |
| T13 | 升科技 | 克制落后 / 金币长期 >700 | 升科技 | `_sanity_research()` | **留桩** |
| T14 | 升科技 | 研究完成 / 切换完成 | 试探 | 无 | **留桩**（停 60 s 兜底） |
| **T15** | 试探/加强/换目标 | **换目标次数 ≥ 2**（方案 A）或**距首次换目标 ≥120 s**（方案 C 兜底） | 攒大波 | 无（进入 B4 目标评分） | `_switch_count` / `_first_switch_t` |
| **N0** | 任意 | 判定 = **未判** | 不转移（继续打） | 无 | verdict（**不得当"差"**） |

> **2C-3 判定入口**：状态机不再读"存活比 / 投入产出比"，改读 §3.12 的判定表输出
> `达成 / 好 / 一般 / 差 / 未判`。`losses_mine / losses_enemy / roi / net_ratio` 仍落表，
> **只作辅助记录与交叉验证**，没有任何转移读它们。
> `--verdict-mode=old` 可回到 2C-2 的旧口径（存活比 + ROI），只用于对照。

**T7 防的是什么**：FFA 下只盯一家打，两家互耗到残，第三家（本图是队2/队3 不结盟的另一支，
或玩家+盟友）坐大。P6 的"效果递减 → 强制换目标"就是把这个风险写进状态机，
而不是等玩家发现"AI 怎么一直在打同一家"。

**目标切换的候选来源**（T12）：现有 `_war_foes()` 里除当前目标外，按
"距离 + 已知静态防御 + 该目标上次的投入产出比"排序取第一；不引入全知读血量
（当前 AI 本来就全知，但 2C 不新增全知依赖，见 §3.8）。

## 3.4 波次记录表（2C 的实现前提，本轮只设计字段）

一条波次记录 = 一次"出击"的完整生命周期。建议结构（GDScript Dictionary，
挂在 AI 脑上，最多保留最近 8 条，避免无限增长）：

| 字段 | 类型 | 含义 | 数据来源（现有/需新增） |
|---|---|---|---|
| `wave_id` | int | 自增波次号 | 现有 `_wave_index` |
| `t_start` | float | 出发时刻（`Game.elapsed`） | 现有 |
| `units_out` | Dictionary | 出发兵力，按 `def.id` 计数 | 现有（`_manage_waves` 的 `push_n` 切片） |
| `cost_out` | float | 投入成本（金+木，C1） | **需新增** `wave_cost(units)`：Σ(`def.gold_cost`+`def.wood_cost`)；`Cfg.unit(id)` 已有字段，无现成汇总函数 |
| `target` | Vector3 | 目标点 | 现有 `_push_target()` |
| `contacts` | Array | 途中遇敌：`{t, enemy_id, n}` | **需新增**（订阅 `Game.combat_hit`，筛本波成员为 attacker/target 的事件） |
| `t_contact_begin` / `t_contact_end` | float | 接敌开始/结束 | 同上（首/末条 contact） |
| `losses_mine` | Dictionary | 我方损失，按 `def.id` 计数 → 成本 | 现有 `Game.unit_died`（带 faction 与 def）；按 def 成本折算 |
| `losses_enemy` | Dictionary | 敌方损失，按 `def.id` 计数 → 成本。**2C-3 起降为辅助记录**（最后一击 +3 s 归属），不参与判定 | `Game.unit_died` + `combat_hit` 的最后一击 |
| `goal_type` / `goal_target_id` / `goal_target_pos` / `goal_name` | String / int / Vector3 / String | 本波目标（五种 + 主基地回退） | 2C-3 目标系统（`_choose_goal`） |
| `goal_achieved` / `t_goal` / `goal_damage` | bool / float / float | 是否达成、达成时刻、本波对目标造成的伤害（识别"达成但他方击杀"） | `unit_died` / 侦查停留 / `combat_hit` |
| `t_combat_begin` / `t_combat_end` / `combat_time` | float | 首次接敌 / 最后一次接敌 / 战斗时间（不含移动） | `combat_hit`，2C-3 |
| `damage_out` / `damage_in` | float | 本波成员作为 attacker / target 的伤害总和 | `combat_hit`，2C-3 |
| `output_actual` / `output_theory` / `output_eff` | float | 实际输出 / 理论输出 / 输出效率 | 2C-3，见 §3.12 |
| `damage_actual` / `damage_theory` / `damage_ratio` | float | 实际承伤 / 理论承伤能力 / 承伤消耗 | 2C-3，见 §3.12 |
| `front_ratio` / `back_ratio` | float | 出发编制里前排 / 后排的人头占比（按 role） | `units_out` + `role_of()` |
| `comp_advice` | String | 构成建议（"补前排/补后排/不调"，**只记录不执行**） | §3.12 C2 |
| `survivors` / `wiped` / `forced_timeout` | int / bool / bool | 存活人数 / 是否全灭 / 是否 180 s 强制收尾 | 2C-3 |
| `verdict_mode` | String | old / new（同一次构建里可回滚） | `--verdict-mode` |
| `t_return` | float | 存活单位全部返回/死亡时刻 | 现有 |
| `verdict` | enum | **new**：达成 / 好 / 一般 / 差 / 未判；**old**：效果好 / 快速被消灭 / 一般 / 无接敌 | 由 §3.12 判定表（old 用 C2 + P1） |

派生量（不落表，收尾时一次算好）：`survival_actual = t_return - t_start`、
`survival_theory = cost_out / max(income_60s, ε)`（C2）、`roi = losses_enemy_cost / cost_out`（P1）、
`net_ratio = losses_enemy_cost / max(losses_mine_cost, ε)`（P2）。
**2C-3 起 `roi` / `net_ratio` 只作辅助记录**：没有任何判定或状态转移读它们；
`output_eff` / `damage_ratio` 才是判定输入（两者各自除以自己的理论值，**不相除**）。

**投入成本用哪个函数取**：目前**没有**现成的"一支部队的总成本"函数。
现有的是 `战斗模型.worth_per_cost(def, ...)`（每金战力，口径含木/人口/时间折算，**不能**直接用，与 C1 冲突）
和 `简单AI._cheapest_army_gold()`（只算金）。2C 需要新增一个纯函数，建议放在 `战斗模型.gd`：

```gdscript
static func unit_cost(def: UnitDef) -> float:      # C1：只金+木
    return float(def.gold_cost) + float(def.wood_cost)

static func wave_cost(units: Array) -> float:      # 按编制求和
    ...
```

**损失用哪个事件取**：`Game.unit_died(unit)`——它已经带 faction 与 `def`，
且在所有死亡路径（战斗/技能/拆除）上都会发；不要用 `combat_hit` 反推死亡。
击杀归属另说：`combat_hit(attacker, target, damage, crit)` 有完整三元组，
按"最后一击 + 最近 3 s 伤害占比"归属即可（2C 先做"最后一击"，够用且便宜）。

## 3.5 哨塔智能摆位（设计建议，因子与权重待商量）

**用户已确认方向**：不用地图 `.tres` 标注战略要点，由 AI 自己算。

| 因子 | 数据来源 | 计算成本 | 依赖记忆层 | 说明 |
|---|---|---|---|---|
| 己方控制区边缘 | 己方单位/建筑 `sight_range` 圆并集边界 | 低（几十个圆） | 否 | 往"视野缺口"补，最直接减少被绕后 |
| 最近战斗位置 | `Game.combat_hit` 最近 60 s 的质心 | 低（滚动静默计数） | 否 | 打起来的地方值得插眼 |
| 地图中心 | `MapData` 尺寸（已知） | 极低 | 否 | 先手视野/中场控制 |
| 已知敌方建筑方向 | 记忆层：最后看到的位置 | 低（读字典） | **是** | 朝敌人方向压视野 |
| 已探索资源点 | AI 侧探索图（见下） | 中（圆并集覆盖判定） | 否 | 护矿/护伐木 |
| 去重 | 已有哨塔位置 + 视野半径 | 低 | 否 | 防止两座塔视野重叠 80% |

**渐进落地路径**：

- **2C 第一版：只用前三个不依赖记忆层的因子**（控制区边缘 + 最近战斗 + 地图中心）。
  这样立刻摆脱现在"朝敌方外圈选点"的全知依赖，且不需要等记忆层。
- **2D**：接入最小记忆层后，再加"已知敌方方向"与"已探索资源点"，权重一起调。

**AI 侧探索数据怎么做（不改 `RtsFog`）**：`战争迷雾.gd` 目前**只对玩家阵营**算
（观察方写死为玩家）。AI 阵营的"已探索"先用近似：
**己方所有单位/建筑的 `sight_range` 圆并集**（几十个圆，逐个对候选点做距离判定，
O(候选点 × 圆数)），不改造 `RtsFog` 的网格结构。等 2D 记忆层落地再统一。

**小路防备（诚实标注）**：地图上的"小路/侧翼通道"要靠**连通性分析或寻路图采样**
才能识别，成本高、收益不确定。**建议 2C 不做**，用"哨塔视野覆盖 + 巡逻"兜住；
若 bench 出现"反复被绕后"（定义为：敌方单位首次进入基地 18 m 时，
我方最近哨塔到该点的距离 > 25 m，且该方向无巡逻），再列为 2D 专项。

## 3.6 与现有模块的关系

**战略导演（保留）**
- 保留：计划表选择、姿态（aggression / worker_bonus / allow_patrol / research）、8 s 滞回、
  `build_metrics` 的指标口径。
- 保留：`plan_ratio`（= 现 `army_ratio`）作为计划选择输入。

**移除（已实施 · 2026-11-03）**
- 移除：**出击许可对军力比的依赖**——`_compute_allow_attack` 不再把
  `attack_ratio ≥ 1.35/skill` 当作前置条件；原来那条"家底够厚（`EAGER_ARMY_VALUE`）且
  不落后（`ratio ≥ 0.95`）"的正向条件也一并移除（它同样在读 `attack_ratio`）。
- 保留但降级：`base_threat > 0` 与 `aggression < 0.30` 两条否决（前者是"别送"，后者是"计划说不打"）。
- `attack_ratio` 仍算、仍进 `metrics` / `posture`，但**只记录、不判断**（报告 / A-B-C 三家对照 / 反馈线用）。
- 为什么移除：本轮 bench 证明"军力比"在 4 队 FFA 上是**结构性缺口**
  （实测 0.47~1.0，门槛 1.59），而它同时承担"计划选择"，两个用途互相污染（已拆开，见 §2）。
  2C-2 阶段 A 实测：移除后 seed1 4 分钟，四家 AI 波次 **0 → 2**、拒击 **55 → 0**
  （拒击只剩"家里挨打"一种理由）。

**新增（2C 实现）**
- 波次记录表（§3.4）+ 效果评估器（C2/P1/P2 三条判据）+ 策略状态机（§3.3）+

### 3.6.1 角色标签与"数值可变韧性"（2C-3 已实施）

**问题**：用户会自己改单位数值、攻防关系、增删单位/建筑。旧 AI 在难度档里写死
`{footman:5, archer:3, mage:1}`，还直接 `Cfg.unit(&"peasant") / &"barracks" / &"farm"`。
用户一改表，AI 要么不造新兵，要么把不存在的 id 当默认值。

**现在**：

| 项 | 落点 | 用法 |
|---|---|---|
| `UnitDef.role` | `代码/配置/单位定义.gd` | `frontline / ranged / caster / siege / worker / defense`；留空时 `战斗模型.role_of()` 按能力回退推断 |
| `UnitDef.tags` | 同上 | `heavy / light / anti_air / anti_building / support / light(照明)`，AI 用 `has_tag()` 读 |
| `UnitDef.design_power` | 同上 | **用户填的战略定位值；AI 决策不读**，只在报告里与 `computed_power` 并列对照 |
| `DifficultyDef.role_weights` | `代码/配置/难度定义.gd` | `{frontline, ranged, caster, siege}` 权重；旧 `composition` 仅作 .tres 兼容回退 |
| 选兵 | `简单AI._pick_army_unit()` | 候选池 = `Cfg.units` 里 role 权重 > 0 的非农民 UNIT；权重 = `selection_weight()`（每金战力 × role 权重 × 过载惩罚） |
| 农民/主基地/农场/兵营/箭塔/哨塔/铁匠铺/伐木场/营火 | `战斗模型` 的"定义查询" | 按 `trains / food_provided / researches / role / tags / dropoff_kinds` 等**能力字段**找，不写 id |

**派生量统一入口**（`战斗模型.gd`，全部 `static`、每次调用重算、不缓存）：
`unit_dps / unit_effective_hp / unit_power / unit_cost / counter_multiplier`；
`unit_power = 几何平均(unit_dps, unit_effective_hp)`，`unit_effective_hp` 的减免问
`RtsCombat.armor_mitigation()`（唯一实现），不另抄 0.06/0.72。

**验收口径**：配置回归新增 28 条断言（韧性 A~E 15 条 + 3 条角色标签 + 7 条判定表 + 3 条理论值）。**"新增 role=ranged 的假兵 → 不崩且进入候选池"** 与
**"删除 archer → 不崩、配比自动重排"** 是硬门槛。

## 3.10 运营线（2C-2）

> 这一节是给后续 agent 看的**禁令**：**保留金闸已经删了，不要再加回来。**

| 项 | 2C-2 之前 | 现在（2026-11-03） |
|---|---|---|
| 花钱判据 | `gold - cost >= reserve_gold(150)` 且 `wood - cost >= reserve_wood(40)` | **钱够就花**：`Game.can_afford()`（金 + 木 + 人口） |
| 覆盖范围 | 军队单独豁免（2C-1），建筑/农民/哨塔/兵营/农场/营火仍过闸 | **全部**走"钱够就花"，`_can_spend` 与 `_can_spend_army` 同一实现 |
| 军队 vs 建筑 | 建筑先动钱（兵营/箭塔/圣地/车坊在前），军队捡剩下的 | **军队优先**：先按当前的钱能造几个造几个；队列排满（钱已记在训练上）或满编后，建筑才能动钱 |
| 科技建筑 | 与军队同时竞争 | **最后**：满编之后才考虑圣地/车坊 |
| 支出需求 > 收入 | 没有这个概念，钱不够就整 tick 跳过 | **补经济**：农民目标 +2（上限 10）、采集配比转向金（木材软盈余线 = 最贵建筑木材 × 2）、已在采的农民每 8 s 最多挪 1 人去采金 |
| 硬闸 | 保留金闸（分档） | **禁止**任何"必须保留 X 金/木"的判断；所有优先级都是每 tick 重算的软判据 |

**"降规模"怎么落地**：每座兵营 `MAX_QUEUE_ARMY = 1`，`_pick_army_unit()` 只把**付得起**的
兵种放进候选池 —— 所以"想造 5 个只有 2 个的钱"自然变成"造 2 个"，不会整 tick 空转。
**"想造建筑但钱不够"**：延后到下一 tick（队列没排满就不动钱），同时 `_demand_pressure()`
为真 → 补经济。补经济的判据是**读数**，不是闸：它只调优先级，不阻止任何花销。

## 3.12 效果判定：四样判据（2C-3 已实施）

> **这一节替换 §3.1 的 C2 与 P1 作为判定依据**。C2/P1 的公式与口径不再参与 state machine；
> `losses_mine / losses_enemy / roi / net_ratio` 仍落表，只作辅助记录与交叉验证。
> why：2C-2 实测 22 条记录里 20 条 `roi=0`（击杀归属只认"最后一击 + 3 s"），
> 判定被归属口径压成"一般"，状态机长期停在试探（见 C-2 报告 §4.3/§4.4）。

### 3.12.1 六个量（各自独立，禁止相除）

| # | 量 | 公式 | 数据源 |
|---|---|---|---|
| (a) | 战斗时间 `combat_time` | 最后一次接敌 − 首次成为 `combat_hit` 的 attacker/target；**移动时间不算** | `combat_hit` |
| (b) | 理论战斗时间 `theory_time` | `部队总价值(金+木) ÷ 1000 × 40 s × 1.0` | `wave_cost` |
| (c) | 理论输出 `output_theory` | `Σ(unit_dps × 数量) × combat_time × 0.7` | `单位表` + 战斗模型 |
| (d) | 理论承伤能力 `damage_theory` | `Σ(unit_effective_hp × 数量)` | 同上 |
| (e) | 实际输出 / 承伤 | 本波成员作为 attacker / target 的 `damage` 总和 | `combat_hit` |
| (f) | 输出效率 `output_eff` | `实际输出 ÷ max(理论输出, 1)` | — |
| (g) | 承伤消耗 `damage_ratio` | `实际承伤 ÷ max(理论承伤能力, 1)` | — |

**0.7 系数为什么存在**：近战卡位、远程被切、走到射程内都要时间，实际打不满"纸面 DPS × 战斗时间"。
取 0.7 是保守值，宁可让实际值好看，避免把正常的仗误判成"一般"。
**待 2~3 局长局数据后决定是否调到 0.8 或 0.6**（本轮不调）。

**战斗时间的终点**：用"最后一次接敌"，不是 `t_return`。`quiet` 收尾带 15 s 静默缓冲、
`home` 收尾带返程时间，都不是战斗时间 —— 规格原话是"移动时间不算"。

### 3.12.2 判定表（严格按此实现）

| 目标达成 | 战斗时间 | 输出效率 | 承伤消耗 | 存活 | 判定 | 动作 |
|---|---|---|---|---|---|---|
| 是 | 任意 | 任意 | 任意 | 任意 | **达成** | 存活撤回 |
| 否 | ≥0.8×理论 | 0.7~1.3 | 0.4~0.9 | 任意 | **好** | 存活撤回，下波同比例 |
| 否 | ≥0.8×理论 | 偏离 | 偏离 | 任意 | **一般** | 换目标 |
| 否 | 0.5~0.8×理论 | 任意 | 任意 | 任意 | **一般** | 换目标 |
| 否 | <0.5×理论 | 任意 | 任意 | 全灭 | **差** | 换目标；连续 3 次→攒大波 |
| 否 | <0.5×理论 | 任意 | 任意 | 未全灭 | **未判** | 继续打（**不许当差**） |
| 任意 | 存活 >180 s | 任意 | 任意 | 任意 | **一般** | 强制收尾撤回 |

**"达成"优先于"强制"**：目标在 180 s 前达成 → 立刻收尾判"达成"，不会等到 180 s。
**"未判"不累计"差"**：`_bad_streak` 只在"差"时 +1，达成/好清零，一般/未判既不累计也不清零。

### 3.12.4 目标系统（五种 + 一个回退）

| goal_type | 目标 | 达成判据 |
|---|---|---|
| 侦查区域 | 敌方基地周边 | 任一存活成员进入 6 m 并累计停留 3 s |
| 摧毁哨塔 | 敌方 `role=defense` 且无攻击的建筑 | `unit_died` 命中 `goal_target_id` |
| 摧毁箭塔 | 敌方 `role=defense` 且有攻击的建筑 | 同上 |
| 摧毁分基地 | 敌方外围/经济建筑（本作没有独立分基地建筑，映射到非防御、非主基地建筑） | 同上 |
| 摧毁高威胁目标 | 最近 60 s 对己方伤害最多的敌方单位/建筑 | 同上 |
| 摧毁主基地（回退） | 敌方主基地（`is_dropoff + 空 dropoff_kinds + trains 农民`） | 同上 |

- **B1 初始目标** = 最近的可攻击敌方（只在摧毁类里挑，不把"侦查"算成最近）。
- **B2 紧急反击**：本波成员被谁打，2 s 内转打谁；每 3 s 最多下一次，**不计出口次数**，
  但这次交战的输出/承伤照常计入本波。
- **B3 出口**：一般 → 换（出口 1）；差 → 换（出口 2）。换 2 次或距首次换目标 ≥120 s → 攒大波（T15）。
- **B4 攒大波目标** = `0.4×距离分 + 0.4×威胁分`；`0.2×效果分` **留桩**（需要记忆层，恒 0）。
- **B5 连续 3 次"差"** → 攒大波；中间出现达成/好 → 重置。

### 3.12.5 design_power 的用法（明确）

- AI **不读** `design_power`：用户改数值后 AI 必须跟着数值走，不能跟着"设计意图"走。
- 只在报告里并列 `design_power=X / computed_power=Y`（`computed_power = 战斗模型.unit_power`）。
- 偏差 >30% 且 `design_power > 0` → 报告标"设计定位与数值不符，建议复查"。
- 本轮所有兵种 `design_power` 留 0（等用户填），所以报告只给 `computed_power` 表，不伪造对照。

### 3.12.6 待实测 / 已知限制

1. `0.7` 输出系数、`40 s/1000` 基准、`180 s` 上限都**没有长局标定**；本轮只给分布与敏感性对照。
2. 侦查目标的"6 m / 3 s"是拍的；当前击杀优先级下很少被选中（报告会如实列触发次数）。
3. "分基地"在当前单位表里没有独立建筑，`GOAL_EXPANSION` 实际打的是外围经济建筑。
4. 多波在途时，同一单位可能同时属于两波 —— 它的伤害会同时计入两波（已知口径，报告标注）。
