# 战斗射程口径（2026-11-07 统一）

> 这份文件是**射程数值的唯一说明书**。改任何单位的 `range` / `acquire_range` 之前先读这里。
> 起因：玩家反馈「弩兵实际能打到的地方比地上的圈大一圈，还能隔着黑雾射死没看见的敌人；
> 近战单位的攻击距离也很怪」。

## 1. 定义

`UnitDef.attack_range`（卡上的 `range`）=

> **本单位碰撞圆边缘 → 目标碰撞体边缘，允许的最大水平间隙（米）。**

不是中心距，也不是"武器长度"。

- `0` = 两具身体正好贴住（边缘间隙为零）。
- 近战给 **0.3~0.45**：身体贴住必定打中，同时留一点容差 ——
  单位之间有 `SEPARATION_FACTOR = 1.15` 的分离力，两个步兵会被顶到中心距 1.08m
  （边缘间隙 0.08m），给 0.3 才不会"差 1 厘米打不到"。
- 远程按这个间隙算：弩兵 `8` = 从自己的身体边缘往外 8m。

### 实现（唯一入口）

| 位置 | 作用 |
|---|---|
| `单位.gd::_target_gap(t)` | 中心距 − 目标半径 − **自身半径** = 边缘间隙；建筑量到墙面再减自身半径 |
| `单位.gd::_attack_reach(t)` | 直接返回 `attack_range`；**不再加目标半径**（旧代码加了一次，等于真实射程多算了 2×目标半径） |
| 够得着的判据 | `_target_gap(t) <= _attack_reach(t)` |
| 范围圈半径 | `选择系统._range_ring_radius()` = `attack_range + 自身半径`（建筑 = `attack_range + 占地半宽`） |

> 旧实现：`gap = 中心距 − 目标半径`，`reach = attack_range + 目标半径`
> → 实际允许中心距 `attack_range + 2×目标半径`。步兵 `1.35` 实际能打到 2.35m，
> 而圈只画 1.35m —— 这就是"圈比实际小"的根因。

### 建筑目标（唯一例外）

寻路把建筑占地外扩 1 格，最近的合法站位在墙面外 **1.50m**（见 `建筑.distance_to_footprint`）；
扣掉自身半径 0.5 后边缘间隙仍有 1.0m。所以对建筑目标：

```
_attack_reach(t is RtsBuilding) = max(attack_range, BUILDING_REACH = 1.15)
```

否则"贴到墙边也砍不到楼"（2026-11-06 修过一次，别改回去）。

## 2. 当前数值（卡是唯一真相源）

| 单位 | 卡 id | range | 边缘间隙的含义 | 圈半径 |
|---|---|---:|---|---:|
| 农民 | `peasant` | 0.30 | 贴身 | 0.72 |
| 步兵 | `footman` | 0.30 | 贴身（**基准**） | 0.80 |
| 蒸汽重步兵 | `steam_guard` | 0.45 | 大锤，贴身略远 | 1.03 |
| 豺狼人战士 | `gnoll_warrior` | 0.35 | 贴身 | 0.90 |
| 豺狼人斥候 | `gnoll_scout` | 7.00 | 短弩 | 7.48 |
| 弩兵 | `archer` | **8.00** | 标准远程（**基准**） | 8.44 |
| 法师 | `mage` | 9.00 | 施法距离，略长于弩兵 | 9.44 |
| 箭塔 | `tower` | 11.00 | 从墙面算，压弩兵 3m | 13.0（+2 占地半宽） |
| 哨塔 | `watchtower` | 0 | 无攻击；`detect_radius = 22` 只做预警 | — |

配套约束：

1. **`acquire_range ≤ sight_range`**：索敌不能超过自己的视野。
   全部作战单位都已对齐（步兵 11/11、弩兵 11/11、法师 10/10、豺狼人斥候 13/13、箭塔 11/15）。
2. **看不见的敌人不许锁、不许打**：`Game.is_visible_to()` / `is_node_visible_to()` 是唯一出口。
   - 玩家阵营（含盟友）受战争迷雾约束：单位要"此刻可见"，建筑/资源"探索过"即可；
   - AI 阵营与中立野怪不读玩家的迷雾表（否则 AI 会因为玩家视角而变瞎）；
   - `--qa-reveal` / 没有迷雾节点 → 全部可见。
3. **前摇结束时再验一次**：`_release_attack()` 里目标跑出「射程 + 0.5m」或钻进黑雾 → 收手不结算。
   旧代码只看"目标还活着"，所以会出现"对着空气挥砍""箭已经出手还追着打"。
4. **待机/警戒**用 `_guard_radius()` 索敌（近战约 3.3m）并允许走过去；
   行军（MOVE）只在前方 45% 索敌半径内反应；建筑（不可移动）永远不追。

## 3. 新增单位怎么填

1. 先定它是近战还是远程：
   - 近战：`range = 0.30`（体型特别大给 0.45），`acquire_range = sight_range`；
   - 远程：`range` 取"身位边缘到目标边缘"的直觉距离（弩兵基准 8）；
   - 防御塔：从墙面算，必须**大于**弩兵（当前 11 vs 8），否则塔被白嫖。
2. `sight_range` 必须 ≥ `range`，否则单位打得到却看不见（本文件第 2 节的约束 1）。
3. 改完跑：
   ```powershell
   godot --headless --path . --script 代码/测试/战斗自检.gd   # E 组直接断言口径
   godot --headless --path . --script 代码/测试/配置回归.gd   # 范围档派生
   ```
4. 范围圈不用改：`选择系统._range_ring_radius()` 自动按 `range + 自身半径` 算。

## 4. 参考：为什么会"打得到黑雾里的敌人"

1. `find_nearest_enemy()` 只按阵营 + 半径找人，**从不读迷雾**（它是性能热点，故意不做过滤）；
2. `_acquire()` 拿到候选就锁，`_update_attack()` 只验距离不验可见性；
3. `_release_attack()` 只验"目标还活着"，前摇 0.2~0.5s 内目标跑多远都照样结算。

三处都已按第 2 节约束 2/3 修正。AI 的索敌走同一套 `_acquire`，因此 AI 也不会再"隔雾点杀"。
