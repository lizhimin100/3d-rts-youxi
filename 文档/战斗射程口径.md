# 战斗射程口径（2026-11-08 · R1 锚定版）

> 这份文件是**射程的唯一说明书**。改任何单位的 `range` 之前先读这里。
>
> 玩家 2026-11-08 定下的口径（原话）：
> 「基准 R 的定义是'每 1 点游戏数值对应多少米'，也就是说'基准 1 的米数是多少'——即 R1 要写清楚。
>  定 R1 = 0.015 米/单位：近战 125 = 1.875 米，弩兵 650 = 9.75 米。实测地板 0.30 米，
>  1.875 米远高于地板，近战四组验收稳过。注释写清：R1 = 0.015 米/单位，所有射程和攻击范围
>  都要卡上数值和 R1 这个基准系数相乘得到 godot 编辑器的实际米数。」

---

## 1. 一句话

> **卡上写游戏数值（三位数：125 / 650 / 870），Godot 里用米；两者只差一个 R1。**

```
实际米数 = 卡上数值 × R1        R1 = 0.015 米/单位
```

| 位置 | 作用 |
|---|---|
| `代码/配置/射程基准.gd::R1` | **唯一的换算系数**，定死。改它 = 全游戏所有射程同时缩放 |
| `单位表._def_of_card()` | 读卡时做唯一一次换算：`attack_range = range × R1` |
| `UnitDef.attack_range` | **米**。所有判定（够不够得着、范围圈、AI 阈值）只认它 |
| `UnitDef.attack_range_value` | **卡上那个游戏数值**（125 / 650 …）。界面显示只认它 |
| 单位卡 / 建筑卡 `range` | 人填的游戏数值 |

---

## 2. 为什么 R1 = 0.015 米/单位

换算：

```
近战 125 × 0.015 = 1.875 米
斥候 600 × 0.015 = 9.000 米
弩兵 650 × 0.015 = 9.750 米
法师 730 × 0.015 = 10.950 米
箭塔 870 × 0.015 = 13.050 米
```

安全性来自实测（`代码/测试/射程标定.gd` 对步兵跑四组行为验收，每档重建世界）：

| 组 | 判据 |
|---|---|
| ① 打人 | 走到 6m 外的敌人身边，6 秒内必须起手 |
| ② 打楼 | 走到 6m 外的兵营边，12 秒内必须起手 |
| ③ 四打一 | 四个兵围一个靶，**四个人都要起手** |
| ④ 四围楼 | 四个兵围一栋楼，**四个人都要起手** |

实测结论：**"能不能打到"的地板是 0.30 米**（贴墙直顶让兵能站到墙面外 0.84m 挥砍）。
近战实际 **1.875 米 ≈ 地板的 6 倍**，所以四组验收稳过，不存在"贴着楼砍不到"。

## 3. 当前卡值表（随时可在卡上调）

| 单位/建筑 | id | 卡上数值 | 实际米数 |
|---|---|---:|---:|
| 农民 | `peasant` | 65 | 0.975 |
| **步兵** | `footman` | **125** | **1.875** |
| 豺狼人战士 | `gnoll_warrior` | 80 | 1.200 |
| 蒸汽重步兵 | `steam_guard` | 100 | 1.500 |
| 豺狼人斥候 | `gnoll_scout` | 600 | 9.000 |
| 弩兵 | `archer` | 650 | 9.750 |
| 法师 | `mage` | 730 | 10.950 |
| 箭塔 | `tower` | 870 | 13.050 |
| 哨塔 | `watchtower` | 0 | 无攻击 |

**没有档位、没有倍数表、没有校验工具。** 卡是唯一真相源，改数字就是改射程。
（想"贴得更死"，把数值调小：125 → 100 就是 1.5 米。）

> 派生档位（`定位词表.range_tier`）跑在**米**上：近战 ≤2.5m / 中程 ≤4m / 远程 ≤8m。
> 步兵 1.875m → 近战；弩兵 9.75m → 超远程。改卡值不用动阈值，除非近战数值跨过 2.5m。

## 4. 近战打楼：没有隐藏距离

`BUILDING_REACH`（以前给建筑单开的隐形余量）**已删除**，打人打楼同一把尺。

寻路仍然把建筑占地外扩 1 格（`关卡.BUILDING_BLOCK_CLEARANCE = 1`，绕行走位要用；
实测改 0 会让"沿外墙走 20m"卡住）。所以光靠寻路，兵会被挡在墙面外 2.0~2.5m。

解决办法是**贴墙例外**（不是加射程）：

| 位置 | 作用 |
|---|---|
| `单位._update_attack` | 目标是建筑且间隙 ≤ reach+1.5m 时，最后这段**不走寻路**，直接朝站位点顶 |
| `单位._step_direct` | 直顶判据：**没走进楼里**（距墙面 ≥ 自身半径+2cm）且本来就贴着这栋楼（≤3m） |
| `单位._wall_approach` | 标记"正在砍这栋楼"：允许进那圈净空、免墙内推挤 |
| `单位._attack_reach` | **只返回 attack_range（米）**，对建筑不加任何东西 |

实测（`战斗自检`）：一个步兵砍兵营 → 停墙面外 2.2m、12 秒 7 次起手；
四个步兵从四面围楼 → **四人各 8 次起手**。

## 5. 范围圈（玩家看到的那条线）—— 圈外一定打不到

> 玩家 2026-11-08：「圈要符合含义，**不要在圈外能打到敌人**。」

```
圈半径 = attack_range(米) + 自身半径 + ring_target_radius()
```

`ring_target_radius()` = **全场最大的单位体型**（不含建筑；建筑是走到墙边砍，不是隔着打）。
取最大值而不是固定 0.5，是因为"圈必须是一个上界"：只要目标中心在圈外，就一定打不到。

| 量 | 步兵当前值 |
|---|---:|
| 射程（米） | 1.875 |
| 自身半径 | 0.50 |
| 圈目标半径（全场最大单位体型） | 0.59 |
| **圈半径** | **2.96** |
| 实际最远可打中心距 | 2.88（圈外还能打 = −0.08，即圈完全覆盖） |

`战斗自检` H 组直接断言 `圈半径 ≥ 最远可打中心距`，圈画小了会红。

## 6. 多个近战打同一个目标

**不许所有人冲向目标中心**：

| 位置 | 作用 |
|---|---|
| `单位._attack_spot(t)` | 建筑 → 墙面外扩一圈（沿朝向散开 ±26°）；单位 → `_surround_spot` |
| `单位._surround_spot(t)` | 站到"从目标指向自己"那一侧的外圈 |
| `_update_attack` | 够不着时走 `_attack_spot`；只差一点点时 `_step_direct` 直顶最后半步 |

三个必须同时成立的条件：不走中心 / 落点扣掉到点容差 0.35m / 敌人不算占位。

## 7. 选中与点选（2026-11-08 新增）

- 选中圈的**射程圈**见 §5；**选中标识**（脚下环）是另一层信息，别混。
- **点选的碰撞半径有屏幕像素下限**（`选择系统.MIN_PICK_PX = 16`）：
  镜头拉远时单位在屏幕上只有几个像素，世界半径不够点 —— 现在按当前镜头深度把
  世界半径补到"屏幕上至少 16px"（封顶 3 倍，免得满屏都算点中）。
