# 界面说明（UI 制作 / 操作 / 样式 / 全部口径）

> 这份文档是**界面的唯一说明书**。改任何界面之前先读它。
>
> ## ⚠️ 最重要的一条
>
> **除非玩家本人明确要求改动，否则没被点到的界面地方一律不要动。**
>
> 这条不是客套话。本工程的界面已经被反复"顺手优化"过好几轮，每次都掉东西：
> 选中时该出现的信息被砍掉、没选中时底栏又莫名其妙冒出来、队列表格被改成大小不一。
> 玩家原话："**除非我本人要求改动，不然没要求的 UI 地方不要随意改动**。"
> 所以：**只改玩家点名的地方；其余像素一个都不要碰**，包括间距、字号、颜色、
> 圆角、描边、排序。真要动，先在提交信息里写清楚"为什么非动不可"。

## 1. 界面是怎么做出来的

### 1.1 全部用代码构建，没有 .tscn

`场景/主场景.tscn` 里只有一个 `CanvasLayer` 节点叫「界面」，挂着 `代码/界面/HUD.gd`。
其余控件全部在运行时 new 出来（文档 §8 明确不写 .tscn：布局脆弱、合并冲突多）。

```
界面 (CanvasLayer, HUD.gd)
└── root (Control，铺满视口，承载一份 Theme)
    ├── 资源条（顶部居中：金币 / 木材 / 人口 / 时刻）
    ├── 提示消息容器（资源条下方，最多 3 条）
    ├── 小地图（左上圆盘）+「副官 · 开/关」+「菜单」
    ├── 底栏底板 RtsOrnatePlate（一整块奇幻石金板）
    │   ├── 左卡：选中档案板 RtsDossierPanel（头像 + 两条 x/x）
    │   ├── 中段：队伍网格 RtsSelectionGrid / 建筑面板 RtsBuildingPanel
    │   └── 右段：命令卡 RtsCommandCard
    ├── 等待落点提示（"左键选择建造位置…"）
    ├── 说明气泡层 RtsTipLayer（z_index = 200）
    └── 结束遮罩（胜/败 + 用时 + 击杀 + 重新开始）
```

另外两层不在 root 里，挂在 CanvasLayer 上：**头顶界面**（选中单位血条/状态图标）和
**隐藏 HUD 后的"按 F9 恢复"提示**（跟着 root 一起藏就没人知道怎么恢复了）。

### 1.2 尺寸只从 `界面规格.gd` 来

`代码/界面/界面规格.gd` 的 `metrics(vp)` 是**唯一尺寸出口**：窗口宽高变化时统一重算
（`margins / stats_w / minimap / tile / card_btn_h / band_h / band_max_h …`），
所以 1024×768 到 1920×1080 都不会出现面板互压。

禁止在面板里写死像素尺寸（`custom_minimum_size = Vector2(368, 216)` 这种），
除了"格子数 × 格子尺寸"这类由内容推导的例外。

### 1.3 摆放：绝对矩形 + 0.22s 补间

`HUD._apply_layout()` 是**唯一的摆放出口**。底栏三块走 `_place_smooth()`：

* 锚点全部归零，直接给 `position / size`（设计坐标 = 像素坐标）；
* 目标变了 → `Tween` 0.22s `TRANS_CUBIC / EASE_OUT`；
* 目标没变但几何被容器最小尺寸撑大 → **直接拉回**（否则会停在"上一帧更大"的样子，下沿掉出屏幕）；
* 只有 `_compact_mode` 翻转才播动画（开局第一次不播，否则三块从 (0,0) 滑进来）。

普通控件（资源条/小地图/提示）走 `_place()` 设 anchor + offset，不需要动画。

### 1.4 底栏的两种形态（玩家 2026-11-01 口径，**别自己发明第三种**）

| 形态 | 触发 | 排布 |
|---|---|---|
| **紧凑** | 只选了**一个**单位（或一个"没在干活"的建筑） | `[信息面板][头像+生命/法力][命令卡]` 三块**全部贴右**，左边整片让给战场 |
| **展开** | 多选 / 建筑在训练·研究中 | `[头像+生命/法力][信息面板 → 一路贴到命令卡][命令卡]`，头像滑回最左 |

判据唯一出口：`HUD._compact_bottom()`；建筑是否算"在干活"看 `建筑面板.is_expanded()`。

紧凑形态下**底板从信息面板左缘起**，不再铺满整屏（否则左边留一块空石板 + 一枚纹章，
玩家原话"左边就不要再有多余的空白面板"）。

### 1.4.1 底栏左缘的竖版经验条（玩家 2026-11-08 新增）

| 项 | 口径 |
|---|---|
| 位置 | **底栏石金底板的左缘外侧**（`plate_left - 15`），两种形态都跟着底板走 |
| 尺寸 | 宽 9px、高 = 底栏内高 − 16 |
| 何时显示 | **只选了一个兵**时出现；多选 / 选建筑 / 空选中一律收起 |
| 画法 | 深墨底 + 1px 金边；填充**自下而上**金橙 + 顶部亮线；星级用竖排小菱形（1~3 颗） |
| 悬停 | `词条.exp(unit)`：这一星多少经验 / 还差多少升级 / 下一星叫什么 / 累计经验·击杀 |

* 控件：`代码/界面/经验条.gd`（`RtsExpBar`），**只有 HUD 摆一份**，不塞进任何一张卡里
  （塞进卡里就只在那一种形态下出现）。
* 数据来源：`RtsUnit.exp_value / star_level / exp_need() / exp_to_next()`（口径见 `代码/系统/升星.gd`）。

### 1.5 没选中 → 整条底栏消失（玩家反复强调的一条）

* 判据唯一出口：`_valid_selection()` 为空 → `_hide_band_parts()`；
* 覆盖范围：左卡、中段、建筑面板、命令卡、石金底板 —— **一次全收**；
* 位置：`_apply_layout()` 开头做硬短路（防"某一块留了尾巴"的中间态）；
* 资源条 / 小地图 / 提示条**永远在**，不受影响；
* 回归测试：`godot --headless --path . --quit-after 400 -- --qa-band-check`
  必须打印 `[QA-BAND] 结果：PASS`（选中 → 底栏出现；清空 → 全灭）。

> 为什么单独写一条：这个行为被不同 agent 改掉过至少两次。**它不是"可选优化"，是需求。**

## 2. 怎么操作

### 2.1 鼠标

| 操作 | 效果 |
|---|---|
| 左键点单位/建筑 | 选中（敌方/友军/中立也能选中查看，但不能下令） |
| 左键拖拽（空地起手） | 框选己方**移动单位**（建筑/资源不参与框选） |
| 双击同类 | 选中屏幕内所有同类型己方单位 |
| 右键点地面 | 移动 / 攻击移动（有敌人时自动交战） |
| 右键点敌人 | 攻击 |
| 右键点己方掉血建筑 | **修理**（农民优先，按 0.02 木/点血扣费） |
| 右键点资源 | 采集（农民） |
| Shift + 左键 | 加选 / 减选 |
| 悬停 | 说明气泡（标题 + 正文 + 脚注），由 `词条.gd` 统一供文案 |

### 2.2 键盘

| 键 | 效果 |
|---|---|
| `F9` | 收起/放出整层 HUD（录视频用；菜单里也有同一条） |
| `Esc` | 取消选择（底栏随之消失）/ 收掉手上的建造工具 |
| `Ctrl + A` | 全选己方部队 |
| `B` | 农民：常用指令 ⇄ 建造页 |
| `H` | 驻守（原地警戒，不追击） |
| `F` | 攻击移动 |
| `S` | 停止 |
| `Q` / `X` | 技能（法师火球等，见命令卡角标）。**被动技能没有快捷键**，它只有一格按钮 |
| `Y` | **固定 / 解除固定视角**（锁定时平移、旋转、缩放全部停住，只留给截图和看阵型） |
| 方向键/边缘滚动/滚轮 | 镜头（滚轮缩放） |

### 2.2.1 命令卡上的技能格（2026-11-07）

- **每个带技能的单位都有格子**，包括**被动**（弩兵的「三连发」）——
  玩家要能一眼看出这个兵身上挂了什么，不许"悄悄生效"。
- 图标是**渲图**（`美术/图标/技能/<id>.png`，256²，和单位/建筑头像同一张底版、同一套描边），
  34px，保持原色（不跟着格子的分类色走）。
- 副行只用短词：`开关` / `已开启` / `施放` / `被动生效`。
  解释性长句一律进悬停气泡（142px 宽的格子里放不下，放进去就是省略号）。
- 被动格**点了不执行任何指令**，只弹说明；不给它快捷键角标。

### 2.3 菜单（小地图下方「菜单」）

设置（音量 / **游戏速度** / 副官开关 / 战争迷雾）、队伍、投降、隐藏界面、重新开始。
小地图正下方的「副官 · 开/关」是一条常驻开关：关掉后副官一个单位都不碰。

- **游戏速度**：滑块 0.5× ~ 3.0×（步进 0.25），直接写 `Engine.time_scale`；
  右侧实时显示倍数，下面有「恢复正常速度（×1.00）」一键复位。
  它只改时间流速，不改任何玩法数值（伤害/射程/建造时长全按游戏内秒算）。
- **建筑升级**（哨塔→箭塔）是**读条**的：中段面板显示「升级中 NN% · 剩余 Xs → 箭塔」，
  进度条占的是建造进度条那一条位置；读条期间不能训练/研究，命令卡上的「升级」格显示百分比并置灰。

## 3. 样式规范

### 3.1 字号（只有六级，不再多）

| 常量 | 值 | 用途 |
|---|---|---|
| `FS_CAPTION` | 12 | 脚注、角标、说明里的小字 |
| `FS_BODY` | 14 | 正文、按钮副标题 |
| `FS_SUB` | 16 | 次级标题 |
| `FS_VALUE` | 18 | 数值、按钮主标题 |
| `FS_TITLE` | 24 | 面板标题 |
| `FS_HERO` | 28 | 大标题 |
| `FS_HERO_BIG` | 34 | **铭牌**（选中单位/建筑的名字） |

层级靠"字号 + 颜色明度"两级表达，**不要加第四种手段**（阴影、描边以外的东西）。

### 3.2 颜色

* 正文 `Spec.text_main()`；强调 `Spec.accent()`（金）；警示用暖橙/红；
* 阵营色唯一出口 `Cfg.display_color_for_slot()`，模型染色 / 小地图点 / 选中圈 / 血条
  四处共用同一份；
* 面板底色 `Spec.panel_style()`（深蓝黑，alpha 0.94，1px 冷灰描边）。

### 3.3 底栏底板 `RtsOrnatePlate`（浮雕底板.gd）

**全 `_draw()` 手绘，只在尺寸变化时重画**。叠层顺序（改顺序会立刻变丑）：

1. 外投影 → 2. 石面渐变（28 条色带）→ 3. 石纹 → 4. 石缝 →
5. 纹章（只在真正空出来的中段）→ 6. 内嵌双金线 →
7. 顶檐 + 铆钉 + 壁柱 + 角饰。

**别退回 StyleBoxFlat**（那是一块纯色板，完全没有质感）；
**也别画满网格砌缝**（看起来像表格）。

### 3.4 各面板的硬约束

* **左卡 `选中面板.gd`**：头像 `h-75` + 两行 `♥ 430/430`、`◆ 120/120`（24px 等宽 + 5px 黑边）。
  **不许有进度条、不许有可见底板**（大头像直接浮在石面上）。`content_height()` 返回常数 184。
* **中段单位 `选择网格.gd`**：单选 = 34px 铭牌 + 一根金线 + 三行竖排数值；
  多选 = `名字 ×N` + 每页 16 格（列数按实际数量收），每格 = 头像 + `430/430` + 血条 + 蓝条。
  格子尺寸**不许自己算**：给小 `custom_minimum_size` + 双向 `EXPAND_FILL`，让 GridContainer 拉满。
* **中段建筑 `建筑面板.gd`**：与单位同构；有活干时上段 `[头像][兵种+大进度条][剩余秒]`，
  下段 **L 型队列**（上排 4 + 下排 3 = 一页 7），超过 7 个出页码 `◀ 1/2 ▶`。
  **建造中的工地**走另一套（UI-21）：`[一个农民头像][内嵌剩余秒数的进度条][✕]`，
  整行 46px 高，没有三行数值、没有队列。
  **队列格必须统一尺寸**（不能第一个小、后面大）。左键点队列格 = 取消该条。
* **竖排数值 `数值列.gd`**：行底为空，只用一根 20% 金线分栏；数字 34px 等宽右对齐，
  超过 4 字降 0.72 倍字号；VBox `alignment = CENTER`。
* **命令卡 `命令卡.gd`**：4 列；每格 `btn.name = "指令_<label>"`（自检按名字找）。
  建筑卡片：训练 / 研究 / 集结点 / 取消 / 攻击或视野信息格 /（哨塔另有「升级」）。
* **说明气泡 `说明气泡.gd`**：挂 root、`z_index=200`、**必须在建面板之前建好**；
  `bind(host, 控件, func() -> Dictionary)` 回调在"弹出那一刻"才执行；
  被绑控件 `mouse_filter` 不能是 IGNORE；文案全在 `词条.gd`，**别在面板里现编**。

### 3.5 三条会直接搞坏界面的坑

1. **`Panel` 不按子节点算最小尺寸** → 放进 HBox 宽度恒 0。**用 `PanelContainer`**。
2. **`content_height()` 一律返回常数**（左卡 184 / 中段 224）。返回动态值会自激：
   内容更高 → 底栏更高 → 格子更高 → 内容更高 … 一路上涨到上限。
3. **`Label.clip_text = true` 会把最小宽压成 0**，HBox 只给最小宽 → 标题被截成两个字。
   标题类一律加 `EXPAND_FILL`。

> 多选同类以前是"每个单位各画一个"，3 个弩兵 = 3 个 12m 大圈叠在屏幕上，
> 玩家看到的就是一堆圆圈。射程是单个单位的属性，多选时不构成信息量。
> 不能攻击的单位（农民/哨塔/农场）不画。圈是"细亮线"不是"光圈"，用 `no_depth_test`
> 让它穿过建筑也看得见 —— 玩家要的是"打得到多远"，不是被地形裁掉一半的弧。
>
> UI-16 的 2026-11-07 修正（玩家口径「敌人整个模型都在圈外一些却仍然能打到」）：
> 射程是**边缘对边缘**的间隙，所以最大可打中心距 = `range + 自身半径 + 目标半径`。
> 旧圈少算了目标半径（0.5m），敌人在圈外半米仍挨打。现在把标准目标半径画进去：
> 步兵圈 = 1.0 + 0.5 + 0.5 = 2.0m，实测"最远可打中心距"也是 2.00m —— 两套数对齐。
>
> UI-17 的边界（2026-11-07 玩家口径「像贴图，一点透视和遮挡都没有」）：
> 旧版是一张**水平方片贴图 + `depth_test_disabled`** —— 斜坡上悬空/切土，
> 山体挡在前面也照样画在屏幕上，看起来就是贴了一张纸。
> 现在：1) 网格逐顶点 `RtsWorld.height_at()` 采样，圈跟着坡面起伏；
> 2) shader 去掉 `depth_test_disabled`，建筑/山体正常遮挡（人物腿会挡住后半圈）；
> 3) `top_level = true` 不吃单位上坡时的俯仰；
> 4) 线宽 0.032m（按 UV 反算，不随半径变粗）、柔光 0.16、不透明度 0.86。
> 建筑圈按占地半对角线罩住，不会切进四个角。
