# 程序化树木方案评估（procedural-tree → 本项目）

> 参考实现：https://github.com/nicoo-474/procedural-tree
> 结论先说：**算法能用，而且正好补上本项目"树冠一坨"的短板；但不能照搬，面数和材质数必须砍一个量级。**

---

## 1. 那个仓库做了什么

零模型文件，纯代码长树，管线五段：

| 段 | 做法 | 关键点 |
|---|---|---|
| ① 骨架 | 从根开始逐步前进，每步重算方向 | 3D Perlin 噪声弯曲（**剔除沿枝方向的分量**，否则枝条会"抽搐"）+ 向光性（向上）+ 重力（向下）+ 递归分叉 |
| ② 主枝 | 主干贯通到顶，主枝在 46%~92% 高度轮生 | `limbRise:[下,上]` 下平上陡 → 穹顶冠；写反立刻变蘑菇头 |
| ③ 管道 | 每根枝扫成 6 边圆管，全部合并进一个 BufferGeometry | **平行传输标架**（不用 Frenet，避免曲率突变处麻花）+ 顶点色伪造 AO |
| ④ 叶片 | 每片叶一个 4×4 矩阵，InstancedMesh，Canvas 现画的镂空轮廓 | 分三层撒叶（末梢 1.0 / 倒二 0.62 / 倒三 0.14），否则"光杆挂绒球" |
| ⑤ **球形法线** | 分杈时给每个子枝一个 `gid`，同一杈的叶归一组，法线 = 叶位 − 该杈球心 | 几千张卡片按"一团是一个球"打光，冠内明暗连续；单色是配套条件，不是偷懒 |

代价（作者自己也写了）：橡树约 **4.3 万三角面**、没有 LOD、单色偏平、导出 GLB 不含动画。

## 2. 对照本项目：哪些能直接搬

| 模块 | 判定 | 说明 |
|---|---|---|
| 骨架生成（噪声/向光/重力/分叉/黄金角方位） | ✅ 直接搬 | 纯数学，无引擎依赖，`tree.js` 的 `samplePath()` + 递归分叉可原样转 GDScript / Python |
| 平行传输管道 + 6 边截面 + `pow(t,0.72)` 收细 | ✅ 直接搬 | 与本项目"顶点色当 AO"的口径完全一致（建筑/地形都在用顶点 AO） |
| 顶点色 AO（按层级 + 圆周角余弦） | ✅ 直接搬 | 免费拿到体积感，不用烘 AO 贴图 |
| **球形法线** | ✅ 最该搬 | 本项目树冠"一坨/和石头一个色"的根因之一就是卡片各自打光。**烘进顶点法线即可，Godot 侧不需要 `onBeforeCompile` 那种注入** |
| 单色叶片 + 冠内明暗靠法线 | ✅ 直接搬 | 和 `自然材质.gd`「一棵树一个色 + 灰度当细节」的做法同源 |
| 三层撒叶密度、`leafStart` 控制露不露枝 | ✅ 直接搬 | 参数化，按 RTS 视距调 |
| 树枝穿地即止（`p.y < 0.06` break） | ✅ 直接搬 | 本项目树要贴地形高度，这条必留 |
| 叶片阴影 `customDepthMaterial` + alphaTest | ⚠️ 换等价物 | Godot 侧 = 材质 `transparency = ALPHA_SCISSOR` + 阴影投递；不用自己写深度材质 |
| 关掉叶片互相受影 | ⚠️ 换等价物 | 对应"树冠内不要接阴影"，靠 `cast_shadow` / 光照层控制 |
| 接地柔影贴片 | ❌ 不用搬 | 本项目已有 `单位视觉._add_ground_shadow()` + 建筑地基台 |
| GLB 自写打包器 / three.js / InstancedMesh | ❌ 不用搬 | 本项目走 `模型工厂` + `装饰库` + `_中/_远` 后缀 LOD |
| 风（顶点着色器 + uniform） | 🟡 可选 | 本项目目前**没有**树的风摆；要的话自己写 spatial shader，别搬 three.js 那套 |

## 3. 成本账（必须先算）

本项目实测：

```
树    2460 面 / 5 网格 / 5 材质（自然_leaf* / 自然_bark*）
草丛   312 面   岩石 280 面   金矿 1308 面
单局树数量：7 簇 × 2（点对称）× 8~14 ≈ 112~196 棵，加基地环 12~17/家和枯木 → 约 150~250 棵
```

现役总面数 ≈ 200 × 2460 ≈ **49 万面**（已经是树林占大头）。

如果照搬那个仓库的橡树（4.3 万面）：200 × 43000 = **860 万面** → 手游直接爆，不可行。

**可用区间**（按现在的总预算反推）：

| 档 | 目标面数 | 参数取法 |
|---|---|---|
| 近（≤46m） | 2000~2600 | 层级 4~5，叶片 500~700 张，管截面 5~6 边 |
| 中（46~96m） | 600~900 | 层级 3，叶片 150~200 张，截面 4 边 |
| 远（>96m） | 120~200 | 层级 2，叶片 0，只剩主干 + 3~5 根主枝（纯剪影） |

命名直接对齐现有约定：`美术/模型/树.glb` / `树_中.glb` / `树_远.glb`，`模型工厂` 会自动挂 `建筑LOD.gd` 式的三档切换，不用改代码。

## 4. 三个必须改的地方

1. **材质数从 5 降到 2**：叶（1 个，单色 + alpha scissor）+ 干（1 个，顶点色）。
   现在 `树.glb` 用了 5 个材质（leaf_light/leaf/leaf_dark/bark/bark_dark），靠颜色分区而不是法线，
   这是"一坨"的另一半原因 —— 球形法线方案本来就要求**单色**，正好一起收掉。
2. **叶子用 alpha scissor，不要 blend**：手游 overdraw 是硬成本；镂空轮廓一张 128² 的单色图就够，别画渐变。
3. **许可**：仓库**没有 LICENSE 文件**。别整段拷源码；按 README 的数学描述重写（噪声剔除切向分量、平行传输标架、球心法线这三条都是公开做法），
   或者先去问作者要一个 MIT。

## 5. 落地路线（建议）

**离线生成资产，不在运行时长树** —— 树是可采集物（要选中、要砍伐、要贴地形），运行时生成的收益为零，风险却是帧率。

1. 写 `工具/建模/v8_树/生成树.py`（复用现有 Blender 管线 `E:\tmp\blender_ok\blender.exe`），
   把 `samplePath` + 递归分叉 + 平行传输管道 + 球心法线翻成 Python，按档位参数出网格。
2. 生成矩阵：**4 个树种（阔叶/松/柳/枯）× 3 档 × 3 个变体 = 36 个 glb**，
   直接覆盖 `美术/模型/树.glb`、`树_中.glb`、`树_远.glb` 与 `树_B*`、`树_C*`（`关卡` 按变体随机取，免得一片林子一个样）。
3. 叶色：接 `调色板.gd` 的生物群系（temperate / arid / snow / volcanic / swamp），
   一个群系一个叶色 —— 和地图编辑器那 5 种地形类型天然对上。
4. 材质名统一带 `自然_` 前缀（`自然材质库` 会跳过它们，不会把生成好的颜色又刷成灰度）。
5. 验收：`工具/检查自然资产.gd` 直接量面数；再拍同机位近/中/远三张对比现在的树。

**总计改动量**：新增 1 个 Python 生成器 + 36 个 glb + 材质 2 个，**引擎代码 0 行改动**（沿用 `_中/_远` 约定）。
唯一可能要碰的：双面叶片如果被 Godot 在背面翻转法线（`FRONT_FACING`），要在叶片 shader 里把法线钉回烘焙值 —— 这一点生成后实测一次即可。
