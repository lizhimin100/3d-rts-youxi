# 编辑器资产同步规范（新增单位/建筑必须能被地图编辑器摆放）

> 玩家口径（2026-11-01）：
> **"只要是新增加的单位、建筑（无论什么阵营，包括野怪）都要同步放入编辑器中，
> 编辑器也能正常摆放和设置。"**
>
> 换句话说：**游戏里能出现的东西，编辑器里必须能找到、能放下、能设归属、进图后长得对。**
> 只加 UnitDef 不加编辑器支持 = 这个内容只能靠代码刷出来，地图作者永远摆不了它。

---

## 1. 为什么"加个 UnitDef"通常就够了

地图编辑器的资产清单**不是手写列表**，而是现场从 `代码/配置/单位表.gd` 的
`build_units()` 算出来的（`addons/map_editor/资产目录.gd` → `MapAssets.all_assets()`）：

| `UnitDef.kind` | 落到的分类（对象页分页） |
|---|---|
| `RtsConst.Kind.UNIT` | **单位** |
| `RtsConst.Kind.BUILDING` | **建筑** |
| `RtsConst.Kind.HARVESTABLE` | **资源** |
| 装饰（白名单 + `美术/模型/v7_自然/` 目录扫描） | **装饰** |

所以"单位表里登记过"是**第一必要条件**，不是充分条件 —— 下面 4 种情况会翻车。

---

## 2. 四种必须额外处理的情况

### 2.1 模型是"组合件"（`model_path = "combo:<key>"`）

营火这类**不是一个 glb**、由多个部件拼出来的建筑，`ResourceLoader.exists("combo:xxx")`
永远返回 false。必须在两处登记：

1. `代码/美术/组合件.gd` 的 `ALIAS` 里加一行 `key → 中文名前缀`；
2. 写 `代码/美术/<中文名>外观.gd`，提供
   ```gdscript
   static func build(def: UnitDef) -> Node3D
   ```

游戏侧（`单位视觉.gd`）和编辑器侧（`预览工厂.gd`）都读这同一张表，
**编辑器所见 = 进图所见**。漏了第 1 步的典型症状：编辑器里放下去是一块**棕色占位方块**。

### 2.2 建筑图标（命令卡 / 信息面板头像）

优先级：`美术/图标/建筑/<id>.png`（渲图）→ `命令卡._icon_for_building()` 的兜底 svg。

新建筑建议跑一次渲图工具（有资产包模型时）：

```powershell
python 工具/渲染建筑图标.py      # 产出 美术/图标/建筑/<id>.png
```

没有 png 也能用，但要在 `_icon_for_building` 里补一条 fallback
（例如营火 → `fire`、哨塔 → `eye`），否则按钮上是空白格。

### 2.3 玩家能造它吗

* 只有农民能造 → 必须加进 `代码/界面/命令卡.gd` 的 `build_page_ids()`。
  **不加 = 玩家点不出来**（编辑器能摆、游戏里造不了，这是最容易漏的一条）。
* 界面自检 `代码/测试/界面自检.gd` 会断言建造页数量，**加建筑要同步改那个数字/文案**。

### 2.4 阵营 / 归属

* 编辑器「对象」页顶部有**「摆放归属（先选玩家）」**药丸：中立 / 玩家 1..N。
  放单位与建筑前先点一个归属，放下去的 `MapObject.owner` 就是那个槽位；
* `owner = -1`（中立）：单位/建筑默认**不会**自动加入任何阵营 —— 例外是**野怪**。
  `gnoll_warrior` / `gnoll_scout` 在 `MapAssets.NEUTRAL_OK` 白名单里，
  可以保持 `owner = -1`；进图后由 `地图加载器` 落到 `Game.neutral_faction`
  （打人、还手、上小地图、AI 认它是敌人）。
* **野怪只由玩家在编辑器里摆**：代码自动撒营地/定时补怪/入夜扑家
  **已于 2026-11-01 整块删除**（玩家口径"是代码刷新就删除，我自己来放置"）。
  营地那种"可配置刷怪点"是未来功能，规格见 `文档/野怪营地.md`（本轮不实现）。

## 3. 新增内容的标准流程（照抄这份清单）

1. **单位表**：`代码/配置/单位表.gd` 里 new 一个 `UnitDef`，填
   `id / display_name / kind / model_path / max_hp / footprint / sight_range …`。
   *`id` 用英文小写下划线，和 `MapObject.type_id`、地图文件、AI 配置共用同一个字符串。*
2. **外观**：`model_path` 填 glb 路径；组合件则按 §2.1 登记 + 写外观脚本。
3. **编辑器**：什么都不用做（自动出现在对象页对应分类）。
   *除非* 它是组合件（§2.1）或需要新分类。
4. **玩法接线**（按需，缺一不可）：
   * 玩家可造 → `命令卡.build_page_ids()`；
   * 建筑可训练 → `UnitDef.trains` + `UnitDef.train_time`（**没有 `build_time` 这个字段**）；
   * 可研究 → `UnitDef.researches`；
   * 资源交汇点 → `is_dropoff` + `dropoff_kinds`；
   * AI 会用 → `简单AI._manage_*` 里加一条建筑/出兵决策；
   * 野怪巢穴 → `野怪.gd` 的收编逻辑 + 刷怪表。
5. **图标**：§2.2。
6. **验收**（两条都要跑）：
   ```powershell
   # ① 数据层：资产目录里必须有它，组合件预览不能是占位方块
   godot --headless --path . --quit-after 200 -- --map-editor-test
   # ② 运行时：直接在玩家基地旁生成一只/一座，看它长什么样、能不能站住
   godot --path . --resolution 1600x900 -- --qa-spawn=campfire --qa-hour=22 `
        --shot=_qa/new_thing.png --shot-delay=6 --quit-after-shot
   # ③ 编辑器里真的摆一次：F4 打开「地图编辑器」→ 对象页 → 选中它 → 视口点击放置 → 存盘 → Test Map
   ```

## 4. 编辑器侧当前的资产盘点（2026-11-01）

| 分类 | 内容 |
|---|---|
| 单位 | 农民、步兵、弓箭手、法师、蒸汽卫士、豺狼人战士、豺狼人斥候 |
| 建筑 | 大本营、兵营、农场、箭塔、哨塔、铁匠铺、神秘圣地、蒸汽车坊、伐木场、**营火** |
| 资源 | 金矿、树（程序化，不需要 glb；`tree/tree_春/夏/秋/冬`） |
| 装饰 | 树、草丛、岩石、木桶、木箱、栅栏、旗帜、帐篷、断墙、路标、木桩、营火（doodad 版）、尸骨 |

> ⚠️ **装饰里的「营火」和建筑里的「营火」是两个不同的东西**：
> * 装饰版（`MapObject.Category.DOODAD`, id = `营火`）是纯视觉，**不发光**、不能被拆；
> * 建筑版（`UnitDef.id = campfire`, 分类「建筑」）有血量、能进建造栏、**夜里会亮**。
> 要"夜里照明"就用建筑版。

## 5. 数据格式备忘

地图文件（`地图/*.tres`）里每个对象只存**纯数据**（`代码/地图核心/地图对象.gd`）：

```gdscript
type_id   : StringName   # "campfire" / "footman" / "gnoll_warrior" / "tree_秋"
category  : int          # 0 单位 / 1 建筑 / 2 装饰 / 3 资源
position  : Vector3      # y 由地形高度决定，存下来只为好看
rotation  : float        # 弧度；建筑会被吸到 90° 档
scale     : float        # 建筑永远按 1.0 处理（占地必须对齐寻路格）
owner     : int          # -1 中立，其余是玩家槽位
properties: Dictionary   # 附加数据：树的 seed/season、装饰的 y_offset …
```

属性页（停靠面板「属性」）能改位置 / 朝向 / 缩放 / 归属；`properties` 这批
"按类型才有意义"的字段由加载器/预览工厂读取（例如 `tools/树` 的 `seed`）。
