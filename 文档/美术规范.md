## 1 风格定义：雕塑感低多边形 + 图形化手绘质感

三根支柱，缺一根就会掉回"方块摞方块"或"塑料玩具"：

### 1.1 雕塑感（形体）
- 形体由 **3~8 个不同朝向的大斜切面**构成；每个部件至少 1 条明显的"削"出来的斜面。
- **禁止纯正交六面体**：任何盒状件都必须至少带以下一项 —— 收分（top≠bottom）、斜切（corner cut）、
  顶部缩进（top_off）、倒角 ≥0.01m。`rts_kit._bh()` 已内建 `bottom/top/top_off/shear` 四个参数，
  建模脚本用它们，不要另写裸 cube。
- 剪影优先：部件"厚/胖/有重量"；**大块与小块交替**形成轮廓节奏（大躯干 → 小腰带 → 大裙摆 → 小靴口）。
- 倒角基线 **0.02~0.06m**（小件按比例缩到 0.005~0.012m）。**不留 90° 死边**：
  真实物体的棱边在光下有 1~2 像素的高光断口，没有倒角 = 一眼假。

### 1.2 图形化（读图优先）
- RTS 相机距离下角色约 40~90 px 高 ⇒ **细节必须做到"剪影/大色块"级别**，不要做手指、镂空花纹。
- 五官/门洞/旗面这类"有没有"比"准不准"重要：宁可放大 1.5 倍，不可缺失。
- 相邻部件必须靠**明度或色相**分开（不可靠"贴得很近"分开）。

### 1.3 手绘质感（明度分档）★ 本次的核心升级
- **同一部件内 2~4 档明度差**，按面法线朝光方向分档（见 §5.2 的分档方向与系数）。
- **暗部偏冷**（+蓝紫）、**亮部偏暖**（+橙黄）。这是"手绘"与"渲染"的最大区别：
  渲染的暗部只是变黑，手绘的暗部是有色温的。
- 关键转折加 **1 条 3~6cm 的深色窄几何带**（真几何，不是 shader 描边）——
  只在**主要转折**加：颈/腰/袖口/靴口/屋檐/基座/门槛。逐面加会糊成一身黑。
- 布料褶皱用 **2~3 道水平/斜向暗带**表达（几何或深一档材质），不要做成锯齿。

### 5.1 基线与例外
| 类别 | roughness | metallic | 例外 |
|---|---|---|---|

| 木 | 0.82~0.86 | 0 | 上油木器 0.74 |
| 皮革 | 0.76~0.80 | 0 | — |
| 布（米白/麻/蓝） | 0.86~0.90 | 0 | 丝绸旗面 0.78 |
| 皮肤 | 0.70~0.74 | 0 | — |
| 钢（刃/甲/盔） | **0.30~0.42** | **0.50~0.60** | 磨亮刃口 0.22 |
| 铁（工具/钉/箍） | 0.52 | 0.45 | — |
| 金 | 0.26~0.30 | 0.50~0.55 | — |
| 描边 / 冷影 | 0.94 | 0 | 永远不吃高光 |
| 发光（火/魔法） | 0.40~0.55 | 0 | emission 6.0 / 7.0 |

**金属的硬规则**：每个金属件必须有**一块 `钢亮` 或 `金亮` 的高光面**（§1.3）。
全件单一金属色 = 读成塑料。做法：把该件最朝光的一片面的材质换成亮档（§5.2 的第 3 档即可覆盖）。

### 5.2 明度分档算法（脚本实现，`style_v2.py::style_pass`）
按面法线与主光方向 `L` 的夹角分 4 档。主光方向取预览三点光的主光（§8）：
`L = normalize(0.49, 0.58, 0.68)`（从前上偏左打来）。

| 档 | 判据 `d = n·L` | 明度变换（在 sRGB 值域做） | 色温偏移 |
|---|---|---|---|
| 3 亮 | `d ≥ 0.62` | **向白抬 24%**：`v + (1−v)×0.24` | +暖（R×1.04, B×0.95） |
| 2 基 | `0.15 ≤ d < 0.62` | ×1.00（基色不动） | — |
| 1 暗 | `-0.45 ≤ d < 0.15` | **×0.72** | +冷（B×1.08, R×0.97） |
| 0 最暗 | `d < -0.45` | **×0.50** | +冷（B×1.16, R×0.94） |

- 明度极差 = 亮档上限 ≈0.985 / 最暗档 0.50 ⇒ **≥1.9 倍**，远超"相邻档 ≥8%、顶/背光 ≥18%"的要求。
- **亮档为什么用"向白抬"而不是乘 1.16**：实测第一版乘法把 `布白 #E8E2D2` 直接夹到 1.0
  （回执 `value_hi: 1.0`），高明度材质的亮档等于没做；改成向白抬之后上限封在 0.985，四档都留得住。
- **薄料明度下限**（`style_v2.TIER_FLOOR`）：茅草 / 麻布 / 白布 / 蓝布亮 / 皮肤 / 叶 / 叶黄
  **永远不许掉到"最暗"档**（最低到 1 档）。依据是物理的：薄料透光，阴影里不会发黑；
  实测动机是农民草帽的帽檐下缘法线朝下（`n·L≈-0.7`），不限档时帽檐变成一条黑杠、把整张脸吃掉。
- **不分档的材质**（`NO_TIER`）：火 / 魔法（发光体分档会破坏"光"的一致性）、阴影 / 描边 / 冷影（本来就是最暗）。
- 只有 1 档意味着"这个面全朝一个方向"（如纯平面），此时**不改**，不硬造假阶。
- 一个部件最多出现 **4 档**，与 §1.3 的"2~4 档"一致。
- 分档材质由基色**推导**，命名 `基色名#亮 / 基色名#暗 / 基色名#最暗`，基色名本身不变
  （保证既有材质引用不失效）。

## 6 部件层级契约

### 6.1 角色（**逐字**，来源：`程序动画.gd` 第 98–103 行）
```
Root
└─ Body                       (原点 = 髋，z = 0.535H)
   ├─ Torso                  (原点 = 腰，z = 0.598H)
   │  ├─ Head                (原点 = 颈，z = chin + 0.10·头高)
   │  ├─ ArmL                (原点 = 左肩关节)
   │  │  └─ ForearmL         (原点 = 左肘)
   │  │     └─ HandL         (原点 = 左腕)
   │  │        └─ Weapon     (原点 = 握点/掌心；空节点，无武器时也保留)
   │  ├─ ArmR → ForearmR → HandR → Weapon
   │  └─ Shield              (原点 = 胸，z = 0.705H；步兵额外挂盾牌网格)
   ├─ LegL                   (原点 = 左髋)
   │  └─ ShinL               (原点 = 左膝)
   │     └─ FootL            (原点 = 左踝)
   └─ LegR → ShinR → FootR
```

三条不可违反的推论（都从源码读出来的，不是猜的）：
1. **`ProcAnim.bind()` 用 `find_child(name, true, false)` 按名绑定，并记下 `n.position` / `n.rotation`
   作为基准**，然后每帧把偏移量加到基准上。⇒ 名字错 = 该部件静默不参与动画（不报错，很难发现）；
   枢轴不在关节 = 动画一跑就"骨折"。**所以枢轴必须落在关节上，这是硬约束，不是风格选择。**
2. `Shield` 与 `Weapon` 在 `需要的部件` 数组里，**4 个角色都必须有这两个空节点**，
   否则步兵以外的单位会少 2 个可用关节。盾牌网格只挂在步兵的 `Shield` 下。
3. 层级深度不可增删中间层：`Body → LegL → ShinL → FootL` 少一层 = 小腿/脚无法单独摆动。

### 6.2 建筑与自然物
```
Root                     (原点 = 底面中心，z = 0)
└─ Body                  (原点 = 底面中心，z = 0；整栋挂在 Body 下)
   └─ <部件网格…>
```
建筑**不需要**关节层级，但必须保留 `Root → Body` 两层：`ProcAnim.bind()` 里
`_已绑定 = _部件.has("Torso") or _部件.has("Body")`，有 `Body` 才算绑定成功（对建筑是空转，但代价为零）。

### 6.3 网格挂载规则
- 网格对象一律**烘焙到世界坐标**（对象变换 = 单位矩阵），父级只做变换载体。
  父级写法只有一种正确形式：`child.parent = parent; child.matrix_parent_inverse = parent.matrix_world.inverted()`
  （`rts_kit.parent_to()` 已封装）。
- `Foot`/`Shin` 等关节下的网格，顶点按**该关节的局部坐标**落位。

## 10 本次交付的已知取舍

- **不为面数做 LOD**：RTS 同屏量不高（≤ 200 单位），单件预算是够的；做 LOD 反而是纯成本。
- **不写 shader 描边**：描边用几何窄带 + 明度分档实现，因为 GLB 里带的是 Principled 材质，
  进 Godot 后是 StandardMaterial3D；用 shader 描边会被导入流程吃掉，还得改 `美术\着色器\`（本次禁区）。
- **不做法线贴图/贴图**：纯顶点色 + 分档材质。理由同上，且 900px 预览下贴图细节看不见。
- **树/岩石的面数上限由本文自定**（任务只给了角色与建筑的口径）：树按"数量最多"给低一档，
  岩石按"纯点缀"给最低档。

# v3 资产契约（2026-10-18 起，骨骼动画 + 参数化染色）

这一节是 v3 美术与引擎之间的**硬接口**。改这里 = 改接口，先改本节再改代码。

## 1. 坐标与朝向
- Blender：x=左右，y=前后（**+Y 是正面**），z=高；脚底/地面 z=0。
- 导入 Godot 后正面 = **-Z**（glTF 会把 Blender 的 +Y 换成 -Z）。
- 建筑在关卡里统一 **rotation.y = PI**（正门朝镜头）；180° 仍是轴对齐，不影响占地与寻路。

## 2. 材质命名协议
- 格式：M_<zone>；队伍色区加后缀：M_<zone>_team。
- zone 取值（引擎 代码/美术/调色板.gd 有同名键）：
  stone / stone_dark / stone_light / plaster / roof / roof_dark / gold / gold_dark /
  wood / wood_dark / steel / steel_dark / steel_light / iron / leather / leather_dark /
  cloth / cloth_dark / skin / skin_dark / hair / crystal / ember / glass /
  bark / leaf / leaf_dark / ore / grass / water / dirt / hay / rope / bone
- 引擎侧 MatKit 只认 M_ 前缀；**不在协议里的材质原样保留**（保护旧资产）。
- 改颜色：编辑 美术/调色板/联盟调色板.tres，或运行时 MatKit.set_zone_color(zone, color)。
  **不要为了改色去重导模型。**

## 3. 骨骼与动画
- 节点：Armature/Skeleton3D + AnimationPlayer（glTF 导入后的默认名）。
- 人形骨架 27 骨：root/hips/spine/chest/neck/head、shoulder/upperarm/forearm/hand ×2、
  thigh/shin/foot/toe ×2、cape.01..03、skirt.F/B。
- **枢轴高度（2026-10-18 修正，硬约束）**：root~head 的骨骼高度必须由 H 推导，与 §3.1 的关节系数一致：
  hips=0.535H、spine=0.598H、chest=0.705H、neck=0.818H、head=0.862H→0.985H。
  旧版把 root~head 写成"比例系数"（0.535/0.62/0.70/0.812/0.862/0.985）而没有乘 H，
  导致头骨在 0.862m、头网格在 1.5m，death 大角度旋转时头会被甩飞；已修，勿回退。
- **aim 的 roll**：`HumanRig.aim()` 必须用 rest 方向 → 目标方向的最小旋转，不能用 ref×d 现搭基
  （会差 180°，脚掌翻面、像倒着跑）；腿用 `pose_rot()` 的关节链局部旋转。
- 动作名（全小写）：idle walk attack shoot cast gather build hurt death
  （建筑只用 idle = 旗面飘动）。缺动作时 SkeletonAnim 会按降级链退到相近动作，不会僵住。
- 循环：idle/walk；单次：attack/shoot/cast/gather/build/hurt/death（death 停最后一帧）。
- ★ **一个单位一套攻击**：`attack` 里只能有一次向前的挥击，不许塞连砍；
  模型里做实验留下的变体动作（idle_b / idle_scratch / 无技能单位的 cast）由
  动作白名单裁掉，永不播放。细则与踩过的坑见 `文档/动画规范.md`。

## 4. 生成与验收
- 单位：blender -b --python 工具/建模/v3/units.py -- all --export
- 建筑：... buildings.py -- all --export；装饰：... props.py -- all --export
- 加 --qc 会在 工具/建模/v3/qc/ 出正/三四视角对照图（固定机位，用来和 单位/三视图 比）。
- 导出后必须 godot --headless --path . --import 让 Godot 重新导入 GLB。
