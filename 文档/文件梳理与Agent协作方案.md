# 文件梳理方案（给后续 Agent 的导航层）

> 结论先说：**要梳理，但梳理的对象是"入口、索引、契约"，不是目录。**
> 这套工程已经有一套很好的文件头注释习惯（171 个脚本里 0 个缺头注释），
> 缺的不是"整理"，是"让 agent 30 秒内找到该读哪个文件"。

---

**核心问题不是"文件多"，是"同一件事有三份实现、三份文档、两种入口"**：

- 训练/研究/建造的可用性判断：`命令卡.gd`、`指令系统.gd`、`建筑.gd` 各一套；
- 波次：`MapDef.waves`（死数据）、AI 进攻波、野怪营地、据点，四套；
- 文档：`界面说明.md` 是铁律，`AI经济与等级排查报告.md` 是历史快照，但两者在目录里长得一样；
- 自检：38 个脚本，21 个能 `--script`、16 个必须进主场景，原因写在各自文件头里，没有总表。

## 2. 为什么**不要**物理搬代码

| 成本项 | 数量 | 为什么 `git mv` 解决不了 |
|---|---:|---|
| `preload("res://…")` | 126 | 字符串路径，不认 uid；移动后运行时报 "Cannot open file"，很多在 `.call` 之后才触发 → **静默失效** |
| 运行时 `load("res://…")` | 109 | 同上 |
| `.gd.uid` | 171 | 只对 `.tscn` 的 `[ext_resource uid=…]` 有效；脚本内部路径不认 |
| 自检入口 | 38 | 命令写死在 `AGENTS.md`、`开发交接.md`、各文件头注释里，`--script 代码/测试/xxx.gd` |
| 编辑器插件 | 13 | `plugin.cfg` 的 script 路径 + 7 处 `界面规格.gd` 反向引用 |

一次搬迁 = 235 处路径替换 + 171 个 uid 跟随 + 38 条命令改文档 + 编辑器插件重编译 + 全量自检。
**收益只是目录好看；风险是重演"编辑器整插件编译失败"。**

所以：**目录冻结，加导航层。**

## 3. 五层导航（做完 agent 就不会迷路）

| 层 | 内容 | 状态 |
|---|---|---|
| **L1 文件索引** | `文档/索引/文件索引.md`（自动生成）：每个文件的行数/类名/职责/preload 出入/自检入口 + 健康指标 | ✅ 本次已落地 |
| **L2 模块 README** | `代码/<模块>/README.md` × 8：职责/不属于这里/入口/白名单/禁改/自检 | ⬜ 待做（1 天） |
| **L3 契约** | `作战条令.md` 已经是契约，但没进必读清单且部分章节过期；再补 3 份窄契约 | 🟡 半成品 |
| **L4 文档状态** | `文档/README.md`：铁律/现行/设计/历史快照/索引 五档 | ✅ 本次已落地 |
| **L5 测试注册表** | `索引/测试索引.md`：38 个脚本的入口/项数/期望/常红/耗时 | ⬜ 待做（0.5 天） |

### 3.1 L1 怎么用（agent 的标准动作）

```
1) grep 文档/索引/文件索引.md "关键词"
2) 看行数与职责，选 1–2 个文件
3) 只读函数头与目标函数（≤200 行）
4) 不要在 7000 行的文件里从头读
```

索引里的"被 preload"列还有一个副作用：**它天然标出了枢纽**。`界面规格.gd`（被 20 个文件 preload）、`战斗模型.gd`（13）、`单位表.gd`（11）——动它们之前先想清楚。

### 3.2 L2 模块 README 模板（30 行以内）

```markdown
# 代码/ai

- 职责：决策（战略/目标）→ 计划（诉求/预算）→ 执行（下令）
- 不属于这里：战斗结算（系统/）、单位状态机（单位/）、界面文案（界面/词条）
- 唯一入口：SimpleAI._think_once / 命令调度.flush
- 对外可调用（白名单）：SimpleAI.set_process、Adjutant.is_enabled/set_enabled
- 禁改：`_exec_*` 之外的函数不要直接下单；不要在 AI 里读 UI
- 自检：`--ai-bench --seed=1 --minutes=10`、`副官自检`
- 已知坑：默认 dept=on，旧 off 分支是死代码；四条下令通道只有一条受仲裁
```

### 3.3 L3 契约：先补最烫的三条边界

不用重写 `作战条令.md`，只补三份"窄契约"（每份 1 页）：

| 契约 | 冻结什么 | 现在的问题 |
|---|---|---|
| **UI ↔ AI** | `Adjutant.is_enabled()/set_enabled()/reserve_text()` | HUD 直接 `_adjutant.get("enabled")`，还在气泡里写死 480 金/140 木 |
| **AI ↔ 单位** | `order_*` 白名单 + `control.claim_ai` | AI 直读 `u.hp`、`get("_repair_target")`、`get("_build_site")` |
| **编辑器 ↔ 运行时** | `MapDef/MapLoader` 只读边界 + 可建造性唯一出口 | 三套"能不能建"（编辑器不查树、运行时不查编辑器掩码） |

另外给 `作战条令.md` 加一行状态：**"§1–§11 为早期契约，§6 单位 API 仍有效；数值与 AI 章节已过期，以代码为准"**——否则 agent 会照着它写老接口。

## 4. 上帝类怎么拆（按 ROI 排序，不是按行数）

> 原则：**先拆"规则"，再拆"状态"，最后才拆"流程"。** 反过来一定炸。

| 顺序 | 拆什么 | 工作量 | 风险 | 收益 |
|---|---|---|---|---|
| **1** | `命令卡.gd` 里的训练/研究可用性判断 → 下沉到 `建筑.can_train_reason()/can_research_reason()` | 1–2 天 | **极低** | 消除 3 套重复规则；UI 只渲染 reason |
| **2** | `HUD.gd` 的 QA 段（约 250 行）→ `工具/qa_hud.gd` | 1 天 | 低 | 生产 UI 里不再有测试旁路 |
| **3** | `简单AI.gd` 的纯函数（目标提案/诉求分/编队）→ `ai/决策/*.gd` 静态模块，入参是 ctx 字典 | 1 周 | 中 | 7531 → 约 5000；可单测 |
| **4** | `简单AI.gd` 的执行器 `_exec_*` → `ai/执行.gd`，`简单AI` 只留编排 | 1 周 | 中 | 7531 → 约 1000 |
| **5** | `单位.gd` 的采集/建造/移动 → `GatherCtl/BuildCtl/MoveCtl`（门面转发，不改调用方） | 2–3 周 | **高** | 只在"每周都要改移动/采集"时才值得 |

**第 5 条要特别谨慎**：`单位.gd` 的 34 处 `_go_to`、5 套到点判据、4 个写坐标的控制器互相咬合。拆它之前先把 `寻路评估` 的 P0（单一写位置口）做完，否则拆完只是把混乱分到三个文件里。

**拦截规则**：拆分期间，新功能一律进新文件；不许再往 `简单AI.gd`/`单位.gd`/`HUD.gd` 里加函数。

## 5. 防退化（让索引自己当体检表）

`工具/生成文件索引.py` 每次都会输出：

- 最大的 10 个文件（超过 1500 行就该警觉）；
- 缺头注释的文件数（当前 0，别破例）；
- 读私有字段 / 动态 call / `Game.` 引用 的总数（当前 69 / 1215 / 735）。

建议每周跑一次，数字变大就查原因。**不设 CI 门禁，只做趋势**——这个工程的节奏不适合硬门禁，但适合"数字突然涨了就问一句"。

新增文件头模板（6 行，索引会自动吃到第一行）：

```gdscript
## 职责：一句话
## 属于：代码/xxx（谁调用我）
## 对外：公开方法白名单
## 禁改：不能碰的东西
## 自检：命令
extends Node
```

## 7. 一句话回答

> **需要梳理，但不要搬目录。**
> 把"文件在哪"变成"文件干什么、谁能调、改完跑什么"——索引（已做）、模块 README、契约、测试表，四样加起来 3 天，比搬一次目录便宜，也比搬一次目录安全。
