## 0. 一句话结论（先看这个）

1. 加完 `class_name` **先跑 `--import`**；需要强类型的地方**改用 `preload` 常量**，别写类名。
2. 编辑器脚本（`addons/map_editor/`）**只要有一个未声明变量就整条编译失败**，
   表现是输出面板被 `Nonexistent function 'autosave_tick'` 刷爆 —— **根因不在 主屏.gd**。
3. 每轮交付完 `git add -A && git commit`（本项目丢过一整天的工作）。

## 1. `Could not find type "RtsXxx" in the current scope`

### 症状（2026-11-01 实际报错原文）

```
ERROR: res://代码/核心/主场景.gd:29 - Parse Error: Could not find type "RtsDayNight" in the current scope.
ERROR: res://代码/核心/主场景.gd:31 - Parse Error: Could not find type "RtsCreeps" in the current scope.
ERROR: modules/gdscript/gdscript_resource_format.cpp:46 - Failed to load script "res://代码/核心/主场景.gd" with error "Parse error".
```

连带现象：主场景**整个加载失败** → 黑屏 / 没有 HUD / 关卡不建。

### 根因

`var day_night: RtsDayNight = null` 这种"用类名当类型"的写法，编译期要去
`.godot/global_script_class_cache.cfg` 里查这个类。这份缓存可能在下面几种情况下是**旧的**：

* 刚 `git pull` / `git checkout` 到含有新脚本的提交；
* 新加了带 `class_name` 的脚本，但**没有**跑过 `godot --headless --path . --import`；
* 编辑器/游戏在缓存重建的**中间**被打开（缓存写到一半）。

缓存里没有那条 → 类型解析失败 → **整个脚本编译失败**（不是"这一行失败"）。

### 修复 / 规矩

* **能不用类名就不用**：脚本只通过 `.call("...")` 调用的地方，类型写 `Node` 就够了：

  ```gdscript
  const DAY_NIGHT_SCRIPT := preload("res://代码/系统/日夜.gd")
  var day_night: Node = null          # 实际类型 = DAY_NIGHT_SCRIPT
  ```

* **必须用静态方法**（如 `RtsCampfireVisual.build()`）时，改成 `preload` 常量再 `.call`：

  ```gdscript
  const FIRE_VISUAL := preload("res://代码/美术/营火外观.gd")
  _model = FIRE_VISUAL.call("build", def) as Node3D
  ```

* 真的要用类名（`extends SimpleAI`、`as RtsBuilding` 这类）→ **加完立刻**：

  ```powershell
  & $g --headless --path . --import
  ```

这一版已经把 `主场景.gd` 的 `RtsDayNight` / `RtsCreeps` 全部改成 `preload` 常量。**别改回去。**

## 2. 编辑器输出被 `autosave_tick` 刷爆（一秒钟几十条）

### 症状

```
ERROR: res://addons/map_editor/主屏.gd:793 - Invalid call. Nonexistent function 'autosave_tick' in base 'RefCounted (编辑会话.gd)'.
（无限重复）
```

编辑器里所有拖动、笔刷、撤销全部失灵。

### 根因

**`编辑会话.gd` 编译失败**（这次是 `_drag_grab_g` 只在函数里赋值、忘了 `var` 声明）。
脚本对象还在，但方法表是空的 → `主屏._process` 每帧调 `autosave_tick()` 全部失败。

`主屏.gd:793` 已经用 `has_method()` 探过了，所以它**不会崩**，但会每帧刷一条。
**真正的错在控制台更靠前的位置**（会有一条 `Parse Error: Identifier ... not declared`）。

### 排查顺序（照这个来，别从 793 行开始看）

1. 往上翻日志，找第一条 `SCRIPT ERROR: Parse Error`；
2. 那条错误里的**文件名 + 行号**才是要修的地方；
3. 修完重启编辑器，确认 `autosave_tick` 不再刷。

### 规矩

* 在 `addons/map_editor/*.gd` 里**新增成员一定先写 `var`**，再去函数里用；
* 这类文件改完必须跑一次编辑器链路自检（见 §5），它会真的把插件加载起来。

## 3. 会静默毁文件的坑

| 坑 | 表现 | 规矩 |
|---|---|---|
| `Read` 对 ~50KB 以上**静默截断** | 读进来以为完整，`Write` 回去就砍掉半个文件 | 分段读，每次 ≤400 行；小改一律 `Edit`，**绝不整文件覆盖** |
| `--quit-after` / `--resolution` 放在 `--` 之后 | 游戏永远不退出 | 这些是**引擎参数**，必须在 `--` 前面；`--quit-after` 是**帧数** |
| 新 `class_name` 没 `--import` | 到处 "Could not find type" | 见 §1 |
| `Panel` 放进 HBox | 宽度恒 0 | 用 `PanelContainer` |
| `content_height()` 返回动态值 | 底栏自激长高到上限 | 一律返回常数（左卡 184 / 中段 224） |
| `Label.clip_text = true` | 最小宽被压成 0，标题截成两个字 | 标题类加 `EXPAND_FILL` |
| `get_meta("x", null)` | Godot 打一条 ERROR（每帧） | 默认值给非 null（如 `Rect2(-99999,-99999,0,0)`） |

## 3.5 对已释放对象做 `as` / 带类型赋值 = **整个函数静默中断**

### 症状（2026-11-07 实测，日志里几万条）

```
SCRIPT ERROR: Trying to cast a freed object.
   at: RtsUnit._update_anim (res://代码/单位/单位.gd:2915)
```

### 根因

```gdscript
var mine: Node3D = _gather_node as Node3D   # 树被砍倒后 free → 这一行抛错
```

抛错后**不是跳过这一行，而是整个函数直接返回** —— 于是 `_update_anim` 后面的
`visual.play(...)` 全部不执行：动画卡住、矿洞位移不更新、日志被刷爆（每帧一条）。
更阴的是它不会崩游戏，只是「看起来怪」。

### 规矩

* 引用**可能已经被 free** 的节点（树/矿/工地/资源点）时：
  ```gdscript
  var mine = _gather_node          # 无类型接住
  if mine != null and is_instance_valid(mine): ...
  ```
* 循环里更要注意顺序：**先 `is_instance_valid(o)`，再 `o is RtsUnit`，最后才 `var x: RtsUnit = o`**。
* 同类已知点：`_update_anim` 的 `_gather_node`、`_tick_inside_build` 的 `_inside_site`。

## 3.6 `_go_to(force=true)` 必须**立刻重算路径**（否则沿旧路走）

`_request_path()` 开头有 `_repath_cd > 0 → _need_repath = true; return`（0.8s 节流）。
以前 `force=true` 也会被这条挡住：目标已经从「工地中心」改成「墙外那一格」，
单位却继续沿着**上一条路径**走 —— 农民绕着工地转圈、进度 0.00。
现在 `force` 会先把 `_repath_cd` 清零再算。**新指令/新站位/追击换目标一律传 force**。
