# 性能基线（3000 兵压测）

> 2026-11-07。这份文件只干一件事：**同一行参数、可复现地量**。
> 下结论前先跑一遍，别看截图猜。

---

## 1. 怎么跑

```powershell
$g = 'E:/Program Files (x86)/Steam/steamapps/common/Godot Engine/godot.windows.opt.tools.64.exe'
& $g --headless --path . --quit-after 240 -- --stress-units=3000 --perf-long=2
```

- `--stress-units=3000`：在**玩家基地外圈**螺旋铺 3000 个待命步兵
  （待命是最省的状态，测的是每帧固定开销）；
- `--perf-long=2`：每 2 秒打一行 `PERF2 {json}`；
- `--quit-after=240`：跑 240 帧就退（3000 兵时约 40~60 秒墙钟）。

**读哪几个数**（`sys` 里都是"每秒吃掉多少毫秒 CPU"）：

| 键 | 含义 |
|---|---|
| `unit` | 全部单位逻辑（分离/贴地/寻敌/移动） |
| `ai` | 所有 AI 大脑（`ai.ctx` / `ai.econ` / `ai.mil` / `ai.san` 是分项） |
| `fog` | 战争迷雾重算 |
| `hud` | 界面 |
| `proc_ms` | 每帧 `_process` 总耗时（毫秒） |

## 3. 这轮改了什么（为什么快）

### 3.1 AI：一个 tick 只扫一次全表

| 改动 | 位置 |
|---|---|
| `_snap_seq` 每 tick +1，下游按序号判断"算过没有" | `简单AI._think_once` |
| `_combat_units_of` 按「阵营 + 0.4s」**跨 AI 共享**缓存 | `简单AI._combat_units_of` |
| `_foe_census` 一次遍历产出 `by` + `ranked`，四个下游共用 | `简单AI._foe_census` |
| `_threat_units` 先过锚点 AABB，再算平方距离 | `简单AI._threat_units` |
| `_enemy_profile` 按「最强敌人 id + 0.6s 时间桶」缓存 | `简单AI._enemy_profile` |
| `army_value` 按 `def.id` 缓存单兵价值 | `战斗模型.army_value` |
| `ratio_with_profile`：画像由调用方给，不再内部重建 | `战斗模型.ratio_with_profile` |

**最容易踩的坑**：`array.hash()` 当缓存 key —— 它本身就是 O(3000)，等于又扫一遍。
用「阵营 id + 时间桶」。

### 3.2 迷雾：同格只点亮一次

`_mark_faction` 以前对**每个单位**点一个视野圆盘。3000 个挤在一起的步兵 =
3000 个几乎完全重合的圆（每个约 100 格），8Hz 重算 → 三百万次格子写入。

现在按 **4m 粗格**去重：同一格只保留半径最大的那个眼位点亮。
迷雾是"能不能看见"的近似，4m 偏差在画面上看不出来。

### 3.3 计时点

`性能探针.gd` 新增 `ai.ctx / ai.econ / ai.mil / ai.san / ai.mid / ai.flush`。
以后改 AI 先看这几个数，别猜。

## 4. 还没做的（留给下一轮）

|---|---|---|
| `u.sep` | 583~705 ms/s，最大单项 | 分离是 O(n×k) 的邻居查询；可以试"只有移动中的单位才做分离" |
| `u.ground` | 111~134 | 贴地采样；可以按"地形区块静止"跳过整片 |

| AI 后期 | 出兵后会涨 | 现在只测了开局 20 秒；要跑 10 分钟局看 `ai.econ` 是否随建筑数线性涨 |
