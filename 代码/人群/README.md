# 代码/人群

> 状态：现行（2026-11-13 新建）

- **职责**：**数据导向的大群单位管线**（SoA + 20Hz + 线程池 + MultiMesh），与节点制单位**并存但互不依赖**。
- **不属于这里**：主游戏单位逻辑（`单位/单位.gd`）、建造 / 采集 / 技能。这一层只有移动、推挤、渲染、箭矢。
- **唯一入口**：`人群演示.gd`（场景 `场景/人群演示.tscn`）→ `人群模拟.tick()` / `人群渲染.draw_frame()`。
- **禁改**：不要把 `Node3D` 加进 `人群模拟`（整个模块的前提是"零节点"）；热循环里禁止 `int /`、`int %`。
- **线程规矩**：分块函数里**只读**用别名，**写**必须走成员访问（Packed 数组写时复制）。

## 文件分工

| 文件 | 干什么 | 关键常量 / 坑 |
|---|---|---|
| `人群常量.gd` | 索引与容量（1m 格 256²、4m 桶 64²、2m 流场 128²） | 边长必须是 2 的幂 |
| `人群空间.gd` | 计数排序平坦网格（零 Dictionary / 零 Variant） | 每 tick 重建，O(n+4096) |
| `人群流场.gd` | 桶队列 Dijkstra + 3×3 方向平滑 + 双线性采样 | 桶用普通 `Array`（Packed 会 CoW） |
| `人群导航.gd` | 栅格漏斗 + 圆弧倒角 + 路径窗口（两个拐点） | 圆角带 `SKIN=0.12` 余量，零余量会卡墙 |
| `人群模拟.gd` | SoA + 固定 20Hz + 线程池分块 + 看路 / 互让 / 推挤 | 邻居预算 16；方向 pass 每 4 tick |
| `人群渲染.gd` | MultiMesh buffer 一次写 + 位置插值 | 12 float/实例（3×4 行主序，已实测） |
| `人群单位.gdshader` | 顶点着色器程序动画（相位黄金比错开） | `leg_split=0.72`、`y_base=0.85` |
| `人群箭矢.gd` + `.gdshader` | 只记命中时间，抛物线 GPU 现算 | `INSTANCE_CUSTOM=(t0,dur,arc,1)` |
| `人群演示.gd` | 压测 / 演示场（`--crowd-bench=N`） | **必须开窗口**：headless 下 buffer 长度为 0 |
| `人群VAT.gd` + `.gdshader` | 真模型：读 `美术/VAT/` 的烘焙纹理，顶点着色器按帧采样 + 每实例相位错开 | 缺套件自动回退胶囊 |

## 真模型（VAT，2026-11-13）

胶囊体只是"占位"。要看到**真兵种走路**，把骨骼动画烘进纹理，走顶点着色器：

```text
# 1) 烘焙（headless 即可）：idle + walk 两套 clip，30fps 采样
godot --headless --path . --script 工具/烘焙VAT.gd -- --vat=res://美术/模型/方块人/方块人_联盟步兵.glb --vat-name=footman --vat-clips=idle,walk

# 2) 用真模型跑压测 / 拍图
godot --path . res://场景/人群演示.tscn -- --crowd-bench=1000 --crowd-secs=8 --crowd-vat=footman
```

产物在 `美术/VAT/`（**已 gitignore**：单件 3~15MB，一条命令可重建）：
`<name>_mesh.res`（合并 3 surface → 1，UV2.x=顶点序号 / UV2.y=区域 / COLOR=基色）、
`<name>_<clip>.res`（RGBAH，上半位置下半法线）、`<name>.json`（帧数/秒数/包围盒）。

### 三个必须知道的约定

1. **模型正面是 -Z**（骨骼静止坐标实测：盾/武器骨的 z 全为负），引擎主线也用
   `atan2(-dx,-dz)`。但人群模拟的 `yaw` 是 **+Z 约定**（`atan2(vx,vz)`），
   所以 `人群渲染.draw_frame` 里必须 `yaw + PI` —— 少这一下就是"整队背朝行进方向"
   （胶囊体看不出来，换真模型立刻露馅，2026-11-13 踩过）。
2. **`visible_instance_count` 一定要设**：不设时 MultiMesh 会把容量（10000）个实例
   全部跑一遍顶点着色器，缩放 0 的也照跑。实测 100 兵和 1000 兵都是 55fps，
   设成实际数量后 1000 兵 55 → 483fps。
3. **烘焙帧率别乱提**：30fps 采样的 idle 是 108 帧（7336 顶点 × 216 行 ≈ 12MB 纹理）。
   要压显存就 `--vat-fps=10`，代价是快动作会糊。

### 实测（1920×1080，vsync 关，8 s，本机）

| 单位数 | 胶囊 fps | VAT fps | 胶囊 draw call | VAT draw call |
|---:|---:|---:|---:|---:|
| 1,000 | 820 | 483 | 27 | 22 |
| 5,000 | 198 | 127 | 27 | 22 |
| 10,000 | 78 | 53 | 27 | 22 |

结论：**VAT 贵 1.5~1.7 倍帧时间，换"真模型真动作"**；1 万单位仍 >50fps。
主线（20~60 个单位）完全不需要 VAT；它只在人群层/大规模演示里有意义。

## 已知坑

1. **整数除余在多线程里是负加速**（实测 0.5×）。热循环里所有索引都改 `>>` / `&`。
2. `MultiMesh.buffer` 在 headless（dummy 渲染器）下长度为 0，压测必须真实渲染。
3. `Packed*Array` 是写时复制：`var a = arr; a[i] = v` 改的是副本。
4. 军团只写 `slot` 不写 `goal` → 全队"原地列队"（2026-11-13 踩过）。
