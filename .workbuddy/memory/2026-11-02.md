## 2C-1：生产队列空转 86% 的根因 + 确定性止损（分支 ai/round1）
- 根因：`_can_spend()` = "花完还要剩 150 金" ⇒ 最便宜兵 130 → **有效门槛 280**；
  AI·1 金币峰值 263/278 ⇒ 永远差 2~17 金 ⇒ `_pick_army_unit` 候选池被清空（探针 75/75 条
  `pick_empty`，理由 `footman:保留金闸(gold 242 < 135+150)`）。**闸是分档的**：侦察塔 90 →
  门槛 240、农民 75 → 225，都过得去，于是钱被便宜出口反复 reset。
- 修：`_can_spend_army()`（军队不吃金币保留额，木仍留 40），只影响选兵过滤。
  空转 206.0 → 中位 89.2（−57%），兵力 8 → 10（max_army）。
- **`prod_idle_seconds` 口径缺陷**：不区分「该造没造」与「已满编」。改后 65% 采样点满编，
  残留空档 65% 合法，有效空转 ≈31 s。以后判空转要加 `army < max_army`。
- **下一个瓶颈不是运营**：四家同时满编 ⇒ `army_ratio`（相对量）恒 1.30 < 门槛 1.59，
  拒击 55/55 同一条理由。要动的是「出击门槛 × 相对兵力」。
- 确定性：**1 分钟内全局 RNG 调用次数 97=97，但 idle_unit_seconds 108 vs 114** ⇒
  RNG 不是发起者，分叉在移动/到达层。已做缓解：patrol/wave/night 三处散开改
  `_dhash01(hash(u.name), seq)`，选兵骰与进攻骰仍在全局流。bench 口径 = 统计可比。
- 探针写法注意：Godot `String %` **不支持 `%.17g`**，会原样落盘成模板串（白跑一次）。
- 坑：`git update-ref refs/heads/ai/round1` 本机静默失败（返回 0 但不写文件）→
  `mkdir -p .git/refs/heads/ai` 后直接写 ref 文件，再用 `git log` 核对。
