# 短局布局卡（开发工具）

> 状态：现行（2026-11-15）。**不暴露给最终玩家**；与地图编辑器、单位卡同级的内容资产。
> 短局运营（CP / 人口 / 小队 / 建造订单）见 `Documents/短局-运营规则.md`。

布局卡解决四件事：

1. 短局每回合的**固定基础布局**（我方开局建筑/单位从卡里生成，不靠地图手摆）；
2. **槽位绑定**：每个实体在内存里绑定 `slot_id`，后续按 id 查实体、记状态；
3. **血量继承**：进短局时读上一局存档，有该槽位血量就用存档值，没有才用 `initial_hp`；
4. **损毁态 + 复活**：血量归零 → 槽位锁定占用、不可生产/训练；`ReviveSlot(slot_id)` 复活。

## 1. 文件位置

| 东西 | 路径 |
|---|---|
| 布局卡（内容资产） | `Content/data/layouts/*.json` |
| 纯逻辑（解析/校验/血量算式） | `Model/layout/layout_card.gd` |
| 运行时（实例化/槽位/存档/复活） | `Game/core/layout_runtime.gd` |
| 短局存档 | `SaveSvc.root() + "skirmish_layout.json"`（测试模式自动落到 `res://.test_profile/`） |
| 配置入口 | `game.json` → `short_layout` / `short_layout_replace` |

默认卡：`Content/data/layouts/短局_默认.json`（按默认地图的玩家基地坐标，原点选 `townhall`）。

## 2. 卡结构

```json
{
  "version": 1,
  "id": "短局_默认",
  "display_name": "短局 · 默认基础布局",
  "map": "res://Content/maps/主场景地图.tres",
  "origin": "townhall",
  "replace_owner_slots": [0],
  "slots": [
    {"slot_id": "P0_townhall", "type": "building", "id": "townhall", "owner_slot": 0,
     "pos": [0, 0], "yaw": 3.14159, "initial_hp": 1600},
    {"slot_id": "P0_peasant_1", "type": "unit", "id": "peasant", "owner_slot": 0,
     "pos": [1.5, 8.5], "initial_hp": 190}
  ]
}
```

| 字段 | 说明 |
|---|---|
| `origin` | `site` = 相对阵营出生点；`townhall` = 相对"实例化前该阵营的大本营"（地图已摆好基地时用）；`world` = 绝对坐标 |
| `replace_owner_slots` | 实例化前先清掉这些槽位已有的单位/建筑（默认 `[0]` = 我方） |
| `type` | `building` / `unit` |
| `slot_id` | 全局唯一；运行时绑定到节点 `meta`，也是存档 key |
| `pos` | `[x, z]`（米），按 `origin` 解释 |
| `yaw` | 朝向（弧度；建筑会吸 90°） |
| `initial_hp` | **最大血量**（槽位定义值）；不是当前血量 |
| `count` | 仅 `unit`：同一槽位生成几个，内部自动拆成 `id`、`id_2`… 独立槽位 |

### 硬禁止：卡里不能有 `current_hp`

当前血量是运行时状态，只进存档。`--check` 会扫描布局 JSON，出现 `current_hp` 直接判失败
（静态/动态分离）。

## 3. 运行时流程

1. 主场景 `_ready`（短局）挂 `LayoutRuntime`，在关卡/地图对象落位之后、HUD/AI 之前：
   `setup(level)` → `boot()`；
2. `boot()` 读 `Cfg.game.short_layout`（或命令行 `--layout=<路径>` 预留），校验卡；
3. 先抓基地锚点（`origin = townhall` 用），再按 `replace_owner_slots` 清场；
4. 逐槽位生成：建筑吸格贴地 + `set_constructed(true)` + `mark_footprint`；单位贴可走点；
5. 节点 `set_meta("slot_id", ...)`，运行时表记 `instance_id`（不持有 Node 引用）；
6. 读存档：`destroyed` → 不生成（槽位锁定）；否则 `hp = resolve_hp(initial_hp, saved_hp)`；
7. 回合结束 / 胜负 / 退出树：`capture_and_save()` 把每个槽位当前血量（或损毁标记）写回；
8. 单位死亡信号 `Game.unit_died` → 有 `slot_id` 的实体标记损毁、`node_id = 0`。

## 4. 血量继承（关键）

```
有存档该 slot_id 的血量  → hp = clamp(存档值, 1, initial_hp)
没有存档（第一局/新槽位） → hp = initial_hp
存档 destroyed = true    → 不生成（槽位锁定）
```

唯一实现：`Model/layout/layout_card.gd` 的 `resolve_hp()` / `state_of()` / `is_destroyed()`；
运行时只调用，不重写公式。

## 5. 损毁态与复活

- 建筑血量归零：`unit_died` → 槽位 `destroyed = true`、`node_id = 0`；槽位**继续占用**，
  不可生产/训练/提供加成（节点已释放，自然没有产能）。
- 复活接口：

```gdscript
# 长局火堆节点以后直接调；hp 省略 = initial_hp
var node := Game.revive_slot("P0_farm")
# 或直接调运行时
Game.layout.call("revive_slot", "P0_farm", 200.0)
```

复活会重新生成实体、恢复 `mark_footprint`、清 `destroyed`，并立刻写一次存档。

## 6. 调试与自检

```powershell
./Tools/run-game.ps1 --check        # 布局卡可解析 / 引用闭环 / 无 current_hp / 路径有效
./Tools/run-game.ps1 --round-test   # 槽位绑定 / 存档 / 损毁 / 复活端到端
./Tools/run-game.ps1 -- --layout-reset   # 忽略上一局血量，按第一局生成（QA）
```

`--round-test` 默认重置布局存档（否则第二遍跑会少几个兵，测试假红）。
