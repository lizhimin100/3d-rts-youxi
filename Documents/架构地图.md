## 0. 一页速览

| 事实 | 数字 / 证据 |
|---|---|
| 运行时 autoload | 只有 2 个：`Cfg`（配置/输入）、`Game`（游戏状态） |
| 可写全局入口 | ≥150 个：Game 的 20+ 字段 + 4 类静态缓存 + 10 个节点组 + 134 个 `static var` + `Engine.time_scale` |
| 上帝类（>1200 行） | `简单AI.gd` 7531、`单位.gd` 3754、`停靠面板.gd` 2275、`HUD.gd` 2275、`地图生成.gd` 2042、`战斗模型.gd` 1854、`视口.gd` 1819、`编辑会话.gd` 1759、`关卡.gd` 1538 |
| 耦合量化 | `Game.` 735 处、`Cfg.` 246 处、动态 `.call(` 1215 处、`has_method` 308 处、读私有字段 `.get("_…")` 69 处、直接写 `global_position` 41 处 |
| 最健康的两条边界 | ① AI→世界是单向的（世界层零引用 AI）；② A* 只有一条调用链（`单位._request_path → RtsWorld.find_path → 关卡.find_path → GridPathfinder`），AI 不直接调 A* |
| 最脏的三条边界 | ① UI 持有并改写 AI / 建筑 / 单位状态；② 单位类内含战斗、寻路、采集、建造、AI 政策；③ 编辑器与运行时共用 `MapLoader`，但"可建造性"有两套判据 |

一句话总结：**这个工程不缺模块，缺的是"模块之间的门"。** 大部分子系统最后都通过 `Game.` 或 `.call("…")` 直接摸对方，而不是通过接口。

### 1.2 功能视角的六个模块（目录 ≠ 模块）

这是本次排查最重要的一条结论：**"战斗系统"不是一个目录，它横跨三个目录五个文件。** 按目录找代码会找错地方。

| 功能模块 | 实际落点 | 行数量级 | 说明 |
|---|---|---|---|
| **AI 系统** | `ai/` 全部 + `配置/AI*.gd` + `配置/战略计划.gd` | ≈12.2k | 决策（战略导演/目标层）→ 计划（诉求/预算）→ 执行（`_exec_*`）三层，但三层靠 4 个运行时开关组合，共 8 条可能路径 |
| **战斗系统** | `单位.gd` 的 2849–3320 段（判定与状态机）+ `系统/战斗.gd`（公式与落伤）+ `系统/投射物.gd`（远程）+ `系统/技能*.gd`（技能）+ `系统/升星.gd`（成长）+ `ai/战斗模型.gd`（AI 侧评估） | ≈4.3k | 命中判定只有一个比较式，但"近战/远程"有 5 个判据、2 套阈值 |
| **游戏实体** | `单位/` 全部 + `配置/单位表.gd` + `配置/卡/**` + `数据/阵营.gd` | ≈10.7k | 卡（.tres）是数值源，`单位表.gd` 是"卡→UnitDef"的重建器（叠加，不是二选一） |
| **编辑器系统** | `addons/map_editor/` + `地图核心/` + `单位/建筑网格.gd` + `寻路/占格规则.gd` | ≈14.4k | 一个状态中心（编辑会话）+ 两块界面（主屏/停靠面板）+ 独立视口 |
| **UI 系统** | `界面/` 全部 + `操作/`（输入）+ `镜头/` | ≈13.5k | HUD 是唯一摆放出口，但面板内部尺寸大量写死；UI 内含业务规则 |
| **寻路与移动** | `寻路/` + `单位.gd` 的 2233–2847 / 3606–3754 段 + `关卡桥.gd`（预算）+ `关卡.gd`（可走性/占格） | ≈3.5k | A* 本身干净；脏在"末端 2 米"的四个局部控制器没人仲裁 |

## 2. 跨模块耦合

### 2.1 机械统计的依赖矩阵（引用次数，非行数）

只统计 `preload` 与 `class_name` 两类硬引用，测试代码已单列：

| 方向 | 次数 | 性质 |
|---|---|---|
| 编辑器插件 → 地图核心 | 33 | 共用 `MapDef/MapLoader`，合理但双向 |
| 单位 → 美术 | 23 | 实体直接建模型/特效，表现与逻辑同层 |
| 编辑器插件 → 配置 | 23 | 资产目录读单位表，合理 |
| ai → 配置 | 21 | 读难度/诉求系数，合理 |
| 界面 → 配置 | 18 | 读数值做文案，合理 |
| ai → 单位 | 15 | 直接调 `order_*`，**跳过指令系统** |
| 界面 → 单位 | 14 | 面板强类型持有 `RtsBuilding`/`RtsUnit` |
| 系统 → 单位 | 12 | 战斗/技能直接改单位字段 |
| 核心 → 地图核心 | 12 | 建关通道 |
| 单位 → 系统 | 7 | 单位反过来调战斗/技能/升星 |

### 2.2 五类越界（按伤人程度排序）

#### C1 · UI 直接读写 AI 状态

| 证据 | 内容 |
|---|---|
| `界面/HUD.gd:1175`、`1274`、`1283` | `_adjutant.get("enabled")` —— 读 AI 的**私有字段名** |
| `界面/HUD.gd:1253-1255` | 先 `call("set_enabled")`，失败再 `set("enabled")` —— 两条写路径 |
| `界面/HUD.gd:1267-1269` | 用组名 `"adjutant"` 找人，退化到 `current_scene.get_node_or_null("副官")` —— 按**节点名**耦合 |
| `界面/HUD.gd:1289` | 气泡里写死"总留 480 金 / 140 木"，真值在 `配置/游戏配置.gd:84-85` |

**为什么伤人**：改副官的字段名 / 改保留金额 → 不报错，UI 静默失灵或文案撒谎。
**收敛方向**：`Adjutant` 暴露 `is_enabled()/set_enabled()` 与 `reserve_text()`，HUD 只调这两个。

#### C2 · UI 内含业务规则（三层判断，玩家只走前两层）

同一条"训练步兵"链上有 3 层判断：命令卡 → 指令系统 → 建筑。

| 规则 | 出现次数 | 位置 |
|---|---|---|
| 训练资格 | 3 | `命令卡.gd:241`、`指令系统.gd:134`、`建筑.gd:164` |
| 主城等级门槛 | 2 | `命令卡.gd:457`、`建筑.gd:167`（**指令系统不校验**） |
| 队列上限 10 | 3 份常量、2 处拦截 | `命令卡.gd:34`、`指令系统.gd:42`、`建筑面板.gd:42` |
| 资源是否够 | 5 | `命令卡.gd:459/482/511`、`指令系统.gd:140`、`建筑.gd:402` |
| 研究可点性 | 2 套完整实现 | `命令卡.gd:502-557` vs `建筑.research_block_reason()`（`建筑.gd:790`） |

**后果**：UI 认为可点、点下去失败（升级读条期间 `指令系统.request_train` 不查 `is_upgrading`）；人口不足在 UI 上显示为可点；任何脚本直接调 `request_train` 可绕过主城等级。
**收敛方向**：`建筑` 出 `can_train_reason()/can_research_reason()` 单一出口，UI 只渲染 reason，指令系统只做"钱够不够 + 队列满没满"。

#### C3 · 单位类内含战斗、寻路、采集、建造、AI 政策

`单位.gd` 3754 行的实际归属（按函数簇）：

| 行区间 | 内容 | 本该属于 |
|---|---|---|
| 21–173 | 60+ 条手感/碰撞常量 | 移动参数表 |
| 652–806 | 受伤 + 立刻还手 + 视野内追杀 + 农民逃跑 | 战斗 / AI |
| 808–856 | `order_retreat` + 残血收队 + 基地回血 6%/s | **AI 策略** |
| 946–1418 | 12 个指令 API（含**直接 new 建筑**） | 建造系统 |
| 1789–1980、3313–3496 | 采集状态机 + 产出结算 | 采集系统 |
| 1983–2151 | 建造 tick + 工地内部 | 建造系统 |
| 2233–2847、3606–3754 | 移动/寻路/分离/贴地/推出 | 移动系统 |
| 2849–3320 | 射程/判定/站位/索敌/攻击循环 | 战斗系统 |
| 3498–3600 | 动画驱动 + 采矿位移 | 表现层 |

跨模块证据：`_go_to` 在 `单位.gd` 内有 **34 个调用点**（战斗、采集、建造、撤退、巡逻、送资源全在同一个类里内联）；8 处 `Game.toast` 直接生成 UI 文案；`单位.gd:3411` 直接读 `Cfg.difficulty(...).gather_multiplier`。
**为什么伤人**：任何一次"移动手感"改动都在一个 3754 行的文件里，回归面覆盖战斗/采集/建造。
**收敛方向**：不改结构也能先做的——把"到点判据"和"写位置"收成两个出口（见寻路评估 P0）。

#### C4 · AI 全知 + 直读别系统内部

| 证据 | 内容 |
|---|---|
| `ai/简单AI.gd:992-1026` | `_threat_units` 遍历全部敌方单位，**零可见性判断** |
| `ai/简单AI.gd:5422-5431` | `_world_tick` 抄全部敌建筑，连 `hp` 都进快照 |
| `ai/简单AI.gd:2761-2778` | 直接读 `据点.gd` 的 `crate_active` / `CAPTURE_RADIUS` / `value_score()` |
| `ai/简单AI.gd:2205` | 直读 `RtsCombat.attack_mult/armor_mult` |
| `ai/简单AI.gd:1483/2005/7442` | `w.get("_repair_target")`、`u.get("_build_site")` 读私有 |
| `ai/简单AI.gd:7410` | QA 探针在生产文件里**改真实建筑血量** |

**为什么伤人**：难度只能靠数值倍率做，不能靠"情报"；据点加个字段名，AI 静默失效。
