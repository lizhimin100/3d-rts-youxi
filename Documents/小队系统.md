# 真小队（Squad）系统 · 2026-11-21 —— **已被推翻，仅作历史记录**

> ⚠️ 2026-11-22 起现行口径是**单兵制**：没有 `squad_size / formation / squad_radius`、
> 没有阵型槽位与队内分散 AI、玩家也不再有任何战斗指令。本文以下内容全部是**当时的实现**，
> 用来解释"为什么走过这条路"，不要照着改代码。现行规则见 `Documents/单兵制.md`。

> 一句话：**玩家操作的最小单位是「一支小队」，不是一个人。**
> 编制、阵型、寻路、索敌、6 步结算全部在 `Model/Squad/`（纯 C#）；
> `Screens/` 只读 `SquadView` 画胶囊、单条聚合血条和指令标记。

---

## 1. 为什么重建

旧的 `LaneBattle.cs` 里虽然也叫 `LaneSquad`，但它是**一维横道推演里的数组下标**：
没有阵型、没有质心导航、没法被玩家选中。GDScript 侧的"小队"更是只有人口批次账本。
本次重建把「队」做成**唯一的运行时实体**，并把"单兵"从玩家接口里彻底删掉。

## 3. 数据口径

### 3.1 `Content/data/units.json`（每兵种）

```json
"squad_size": 5,
"formation": "square",        // square 方阵 / scatter 散阵 / wedge 楔形
"squad_radius": 110           // 三位数游戏数值；×R1 = 1.65 米
```

* `squad_radius` 是**导航与阵型预算**：质心避障、抵达判定、槽位缩放都读它；
* 槽位生成后若超出 `0.92 × squad_radius` 会**等比缩放**，所以"阵型比队还大"在数据层不可能；
* `UnitCatalog.Validate` 现在的闭环：阵型合法、半径 100..400、槽位数 = `squad_size`、槽位不重合、最大槽位 ≤ 0.92 半径。

### 3.2 `Content/data/squad.json`（小队模式旋钮）

```json
{ "zone_dps_per_squad": 18.0 }
```

* 横道旧口径是 9 血/秒/队；小队是战斗实体，抽血口径单独给 18；
* 不填则回退到 `levels.json` 的 `lane.zone_dps_per_squad`；
* 单轮时长仍由关卡的 `round_seconds = 90` 决定，这里不重复。

### 3.3 坐标

* **`Model/` 内部只用游戏数值**（R1 = 0.015），不出现米；
* `SquadArena` 负责「世界米 ⇄ lane 游戏数值」的**唯一换算**；
* 桥对 GDScript 暴露的 `SquadView`、`SquadArenaInfo`、`SquadOrder`、`SquadPickWorld` 全部用**世界米**。
* lane：X = 沿战场（玩家 → 敌方），Y = 横向；`heading` 是数学角（+X 为 0），Godot 侧 `rotation.y = -heading`。

## 4. 阵型

* **方阵（square）**：`cols = ceil(sqrt(n))`；前排朝 +X，最后一排居中；列距 = 2.05 × 身位。
* **散阵（scatter）**：黄金角螺旋，半径按 `sqrt(i/n)` 铺开，整体向前偏 10%。
* **楔形（wedge）**：0 号在前，其余按 `rank = (i+1)/2`、左右交错向后展开。
* 所有模板最后都走 `FitRatio = 0.92` 的等比缩放。
* 成员**只跟槽位**：每 tick 向 `质心 + 旋转(offset, heading)` 弹簧收敛（12/s），
  超出 `1.45 × squad_radius` 的牵引绳就拉回 —— 没有独立寻路，也不会"各自乱跑"。

---

## 5. 寻路

输入是 `map_shells.json` 的 `spine.points`（Catmull-Rom 采样点，等价于 Path3D 导出的路径点）：

1. 米 → 游戏数值，建折线图；
2. 相邻点 + 隔点跳边（跳边必须在可走矩形内）；
3. 起点接最近 3 个脊线点、终点只从最近 2 个脊线点出；
4. A*（欧氏启发、同代价按索引稳定排序，确定性）；
5. **走廊平滑**：只有"捷径仍落在脊线 ±走廊内"才允许删点，否则保留脊线点；
6. 局部避障：小队圆-圆分离（按身位，不按阵型半径），每 tick 位移上限 ≈ 0.9 身位/秒；
7. 身体阻挡：敌人在正前方贴住时，把"朝它走"的分量剪掉，沿着它滑（Move 强行军不参与）。

**建筑不进入这张图**：`RouteGraph.cs` 里没有 `TacticalTile`、没有任何建筑/占格查询。
战斗阶段建筑不阻挡小队寻路，`--check` 有一条源码级断言守住它。

---

## 6. 小队原子性

* 选择：`SquadPickWorld`（点任意成员 → 返回整队 id）、`SquadBoxWorld`（质心在框内 → 整队）；
* 指令：`SquadOrder(ids, "move" | "attack_move" | "hold" | "stop" | "attack", x, z, targetSquad)`；
* 成员**没有**对外 id / 指令入口；`SquadView.Members` 只用于渲染；
* 集火是**队级** `target_squad`：成员各自打该队里最近的活人；
* 驻守/停止：清空路径、不移动，只在射程内自动还手。

---

## 7. 战斗与抽血

* 每次出手走 `CombatCalculator.Compute` 的 6 步（命中 → 暴击 → 穿透 → 承伤 → 6×6 克制 → 最终）；
* 远程生成投射物（速度来自 `projectile_speed`），目标死亡则投射物落空；
* 队血 = 所有活着的成员血量之和；成员全灭 = 整队阵亡；
* 小队在敌方势力区（`x ≥ enemy_zone_start`）且 9 米内无敌人 → 按 `zone_dps_per_squad` 抽基地血；
* 建筑（格子左上角）只记录"哪一格有哪座"，不参与碰撞/寻路。

---

## 8. 训练牌 → 格子中心

* `SquadSession` 复用 `PlanningMatch`（CP / 人口 / 建筑 Tag / 星级），**不写第二份规则**；
* `PlanningMatch.PlayTrainOut` 返回「哪座建筑产了哪一队」，`SquadSession` 据此查布局卡的格子；
* 出兵点唯一来源：`TacticalTile.SquadSpawnAnchorWorld()` = **格子正中心**；
* 同一座建筑连出多队时，后续队伍按"出队队列"往自家方向排开 2 米（第一队仍在正中心）；
* 即时模式（试玩）打牌即落地；推演模式（`--simulate`）先规划、开打前统一落地。

---

## 9. 表现层

* 成员 = `CapsuleMesh` + 阵营色（我方蓝 / 敌方红），不造新美术；
* 每队一条聚合血条（54×5 px）+ 人数，选中圈 / 指令落点 / 集火线都画在 3D 里；
* 试玩场景：`Screens/scenes/小队战场.tscn`，根脚本 `小队战场.gd`；
* 操作：左键框选 / 点选 · 右键移动 · 右键敌人集火 · H 驻守 · S 停止 · A 攻击移动 · 空格全选 · 滚轮缩放 · 方向键平移。

## 11. 已知限制 / 待办

* 试玩场景只跑**第 1 轮进攻 60 秒**；第二轮的"防守"还没有接入场景（Model 推演里是两轮）。
* 战斗期玩家只能"选中我方小队 → 右键敌方小队集火"；`1` / `2` 切换 1x / 2x 倍速。
* 试玩场景的建造牌只能落"下一块空玩家格"，没有 3 合 1 的拖拽交互。
* 自动推演是固定战术（全线侧翼 Move 偷家），所以近战 DPS 很低（都在行军）；
  这是战术选择，不是数值 bug。人类玩家用 A（攻击移动）+ 集火会打出更高近战输出。
* 没有 3D 模型/动画；成员是胶囊体，等美术接入后再替换 `小队层.gd` 的 MultiMesh mesh。
* 建筑不阻挡是设计口径；如果以后要"守路口"，应加**地形窄口**而不是把建筑塞进寻路图。
