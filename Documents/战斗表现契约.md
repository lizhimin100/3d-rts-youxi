## 1. 双场景切换入口

`CampaignSession` 是**唯一**的会话状态机（`Model/Squad/CampaignSession.cs`）：

```
CampaignNew(units, combat, planning, level, shell, layout, encounter, battle, seed, instant)
  └─ CampaignBeginPlanning()          # phase=planning，可打牌/建造/升星
       ├─ CampaignTrain / CampaignBuild / CampaignStrategy / CampaignMerge(待接)
       ├─ CampaignFreeTiles()         # 可点格子（严格模式只有 1 个）
       └─ CampaignEndPlanning()       # 固化 ArmyPlan
  └─ CampaignBeginRound()             # phase=executing，round_kind=battle
       ├─ BattleStep(handle, dt) × N  # 推进；返回本帧跳字事件
       └─ BattleSnapshot(handle) × N  # 渲染快照（units[]）
  └─ CampaignSettleRound()            # round_kind=done，扣基地血 + 清场
       ├─ outcome != "" → phase=result（终局）
       └─ outcome == "" → 回到 CampaignBeginPlanning()（**第 N+1 轮重新打牌**）
```

* 场景侧 `Screens/world/battle/战役战场.gd` 的 `phase_name` 只有三个值：
  `planning / battle / result`；`round_kind` 只有 `"" / battle / done`。
* 旧的 `attack / defend` 两段式（`BeginAttack / BeginDefend / EndRound / CampaignSessionDefend`）
  **已物理删除**，不要再按那两个名字接线。
* 关闭会话：`CampaignFree(handle)`；`restart()` 会先 Free 再 New。

## 2. 棋盘：6 列 × 3 行坐标绑定与当前填充位

| 数据 | 来源 | 说明 |
| --- | --- | --- |
| `next_fill_tile` | `CampaignInfo` | 下一个**必须**填的格子号（0 = 已满） |
| `next_fill_col` / `next_fill_row` | `CampaignInfo` | 同一格子的逻辑坐标（列 0..5 / 行 0..2） |
| `CampaignFreeTiles(handle)` | 桥 | 严格模式下只有 `next_fill_tile` 一项；`AllowFreePlacement` 钩子打开后是全部空格 |
| `CampaignBuild(handle, cardId, tile)` | 桥 | `tile=0` = 自动挑顺次位；非顺次位会被 Model 拒绝（`built=false`） |
| `BattleArenaInfo.tiles[]` | 桥 | 每格 `x/z`（格中心，世界米）、`w/d`、`spawn_x/spawn_z`（出兵锚点）、`building_x/building_z`（左上角建筑锚点）、`yaw/terrain_y` |
| `BattleArenaInfo.player_buildings[]` | 桥 | 当前棋盘上的建筑 `{tile, building, star}`（落子后重新读它重建） |

高亮口径：**只高亮 `next_fill_col/row` 这一格**（严格顺次），其余空格不画可点样式；
`AllowFreePlacement` 打开后改用 `CampaignFreeTiles` 全集。

## 3. 天降落子 / 升星金光（`BoardEvent`）

`CampaignBoardEvents(handle)` 每帧排空一次，返回：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `kind` | string | `placed` = 建造牌落位（= `BuildingPlaced(col,row,id)`）；`upgraded` = 3 合 1 升星（= `BuildingUpgraded(col,row,star)`） |
| `tile` | int | 数据里的格子号 |
| `col` / `row` | int | 6×3 逻辑坐标（可直接算世界位：`tiles[col*3+row]` 或按 `tile` 查） |
| `id` | string | 建筑 id（`barracks / watchtower / ...`） |
| `star` | int | `placed` 恒 1；`upgraded` = 新星级（最高 3） |
| `planning` | int | 第几次规划（排序/去重用） |

现状（可直接替换）：

* `Screens/world/battle/战役建筑层.gd` 的 `push_board_events(events)` 是唯一消费点；
  `_fx_placed()` 现在做"从 2.2 m 落下 + 压扁回弹"，`_fx_upgraded()` 做"放大回弹"。
  周末要接粒子/光柱，只改这两个函数，**不要改事件字段**。
* 探针：`board_event_report()` → `placed=N upgraded=M`（`--shot` 可读）。

## 4. 红白跳字（`HitEvent`）

`BattleStep(handle, dt)` 的返回里：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `events[]` | Array | 本帧的伤害事件（已排空，只来一次） |
| `events[].target_id` | int | 被打的单兵 id |
| `events[].amount` | double | 实际伤害（`miss` = 0） |
| `events[].feedback` | string | `crit_or_counter`（红）/ `resisted`（白）/ `normal`（常规）/ `miss` |
| `events[].x` / `z` | double | 命中位置（世界米）—— 直接在上面飘字，不用再查单位 |
| `events[].lethal` | bool | 这一下是否打死目标 |
| `events[].t` | double | 模型时间（秒） |
| `events_dropped` | int | 队列溢出丢弃数（正常 0） |

颜色/文案（表现层只认这四个值，不查克制表）：

```gdscript
match feedback:
    "crit_or_counter": color = Color(1.0, 0.30, 0.24)   # 红
    "resisted":        color = Color(0.97, 0.97, 0.93)   # 白
    "normal":          color = Color(1.0, 0.86, 0.52)    # 常规
    "miss":            text  = "MISS"                    # 灰蓝
```

消费点：`Screens/world/units/单兵层.gd` 的 `push_hits(events)`（Label3D 池）。
硬上限：每帧最多 24 条、同屏 40 个、Model 队列 256 条；超出丢弃并计入 `events_dropped`。

## 5. 队色替换与 model_scale 挂点

| 目标 | 接口 | 说明 |
| --- | --- | --- |
| 兵种/哨塔模型 | `ArtKit.build_model(path, model_scale, fallback_size)` | `path` / `model_scale` 来自 `units.json` 的 `model_path` / `model_scale` |
| 棋盘建筑模型 | 同上 | `path` / `model_scale` 来自 `planning.json` 的 `buildings[].model_path` / `model_scale` |
| 阵营色 | `ArtKit.apply_team_color(root: Node3D, color: Color)` | 铁誓资产包只染两个材质：**`team`（主色）/ `team_trim`（描边金）**；没有 `Mat_TeamColor` 这个材质名，别去找 |
| 运行时改色 | `ArtKit.set_zone_color(zone, color)` | 全场同 zone 立刻变色（不改模型） |

* 玩家色 `Color(0.30, 0.62, 1.00)`、敌方色 `Color(1.00, 0.32, 0.26)`（`战役战场.gd` 顶部常量）。
* 模型的**唯一缩放真值**在 JSON（`model_scale`），代码里不许再乘系数；
  哨塔 `watchtower_bolt` = `哨塔.glb` × 0.18（原尺寸 17.3 m 是地图级，缩放后约 3.1 m 高）。

## 6. 只读信息面板（选中）

`BattleSnapshot(handle).units[]` 一名单兵一条：

| 字段 | 类型 | 用法 |
| --- | --- | --- |
| `id / side / unit_id / display_name / star` | int/string | 身份 |
| `x / z / heading` | double | 世界米 + 朝向（弧度，lane 系：+X = 0） |
| `hp / max_hp / alive` | double/bool | 血条 |
| `state` | string | `march / fight / hold / dead` —— **动画唯一驱动** |
| `state_age` | double | 当前状态持续秒数（`> 0.15` 才换动作，防抖） |
| `moving` | bool | 本 tick 是否真的位移（走路动画用它，不要用"有路径"） |
| `target_id` | int | 正在打/追的目标（弹道拉线用） |
| `order / radius / move_speed / kills / damage_dealt / spawn_tile / source_building / age / body_radius / attack_cooldown` | — | 信息面板与调试 |

## 7. 战败简报

`CampaignInfo.defeat_record`（string）：只有 `outcome == "lose"` 时非空，
格式 `败于第 N 轮（label）；敌方主力击杀：A（x 杀）、B（y 杀）；致命扣血：…，扣 D 点，基地 P → 0。`
胜利结算**不产出报表**（只显示 `battle.result.win` 文案）。
