# 概念：战争原岛（设计真相）

> 本文件是**设计真相**，只回答"这个游戏是什么、已经定了什么、还没定什么"。
> 实现细节在 `Documents/architecture.md`；流程与硬约定在 `AGENTS.md`。
> 规则：被推翻的条目不删除，用删除线 + 作废日期保留。

## 一句话

融合肉鸽构筑与半回合制 RTS 战斗的 3D 策略游戏：玩家是**战场指挥官**——规划阶段（无限时、世界完全暂停）制定战略战术并批量下达命令，执行阶段实时运行、观察战果、必要时亲自接管；部队以 **Squad** 为基本战斗实体，短局运营只用 **CP + 人口 + 训练/建造时间**，长局金币与局内 CP/人口完全隔离；**副官**静默执行常规操作、不弹窗不建议、不得覆盖玩家命令。目标平台 Steam + 低中端手机。

## 已确认

- **类型**：RTS，PvE 为主，肉鸽式单局循环（2026-11-14）。
- **半回合制双阶段**（2026-11-14）：规划阶段无限时、世界 `paused`；执行阶段实时；`Game.set_phase()` 是唯一阶段入口，`SceneTree.paused` 是真暂停。**正常启动默认短局**（半回合制是主线）；`--long` 回旧即时战略；测试/QA 默认长局，`--short` / `--round-test` 显式短局。
- **Squad 是一等公民**（2026-11-14）：命令记录存 `squad_id + unit_ids`，小队是 `Game/systems/小队注册表.gd` 里的 RefCounted 记录（不进场景树、不做碰撞/迷雾）；**不做士气**，成员死亡只减人数，小队继续存在。
- **短局资源**（2026-11-14）：CP + 人口 + 训练/建造时间；CP 成本唯一来源是 `Content/data/game.json` 的 `short_cp_costs`；短局禁采集，农民保留为工程兵。长局金木与短局 CP/人口完全隔离。
- **副官静默执行**（2026-11-14）：短局关闭建议通道（`_maybe_hint_*`），不主动弹窗；不得覆盖有效玩家命令（控制权组仍是唯一保护）。
- **引擎**：Godot 4.7；当前全 GDScript；规则最终迁到独立 **C# 内核**，Godot 只做表现与适配（2026-11-14）。
- **特色**：副官减少操作量、辅助轻量玩家；操作上限仍留给愿意微操的人（2026-11-14）。
- **平台**：Steam + 低中端手机；平台差异只允许出现在 `Engine/platform/`（2026-11-14）。
- **工程地基**：按「七块砖」分层——说明书、自研引擎层、逻辑/画面分家、内容即数据、自带体检、接口代替鼠标、骨架传下去（2026-11-14）。
- **数据真源**：`Content/data/*.json`；文案 `Content/i18n/ui.csv`；资源 key `Content/keys/assets.json`（2026-11-14）。
- **测试默认**：静音、无焦点、隔离存档 `res://.test_profile/`，绝不读写玩家真实存档（2026-11-14）。
- **名字**：项目定名《战争原岛》（2026-11-14）。
- **对局**：保留 4 队混战为主场景（`match_slots = 4`）（2026-11-14）。
- **部门制转正**：AI 部门化决策（`--dept=on`）是默认主线；off 仅作旧路径对照（2026-11-14）。
- **语言**：结构性目录名保持七块砖英文契约；界面/注释/文档/新玩法脚本优先中文，跨语言 key 用 ASCII（2026-11-14）。
- **平台/存档/对话**：只保留接口，暂不接玩法和 SDK（2026-11-14）。
- **音效**：用 AudioStreamGenerator 运行时合成，不再依赖音效文件；音乐仍可用文件（2026-11-14）。
- **地图编辑器**：地图/单位/建筑/技能卡的可视编辑继续由真人维护；agent 只改 JSON 并用检查验证（2026-11-14）。

## 建议（待试玩确认）

> 这些是方向，不是承诺；试玩数据说话。

- **副官全接管**：建造/训练/采集/**战斗**都默认接管；玩家可一键"夺回控制"或关闭副官接管。默认接管比例待试玩。
- **一局时长与目标**：10~15 分钟；每局目标不同——摧毁目标 / 防守 N 分钟 / 占据某据点一段时间。肉鸽层数/词条数量待定。
- **轻量玩家路径**：默认开启副官 + 自动施法 + 一键编队；高操作玩家可关副官、全手动。
- **手机操作**：面板化指令、框选简化、自动索敌；低端机降级项（阴影/单位数/特效）待实测。
- **数值基线**：先保证"同样兵力对撞，胜负由克制与站位决定"，再谈肉鸽词条；当前镜像推演只作 smoke。
- **C# 内核**：`net8.0` 纯类库 + xunit；Godot 只留 Adapter；参考 YokiFrame 的工程分层，不整体引入 QFramework。

## 待决定

- 正式英文名 / 商店名。
- 肉鸽结构：单局内 3 层？局外解锁？失败是否保留部分进度？
- 副官的"性格"与叙事定位（纯工具 / 有台词的角色）。
- 多人/合作是否在范围内（当前只做单机 PvE）。
- Steam 成就与云存档的接入时间；手机平台 SDK 顺序。
- 存档形态：单槽自动存档 / 多槽手动 / 云同步。
- 短局数值基线：CP 起始/上限/回复、执行时长、波次编成、CP 成本，全部待试玩；当前只是可跑通的闭环值。
- 旧 `Game/` 玩法层继续拆进 Model 的顺序与验收标准（先可用性，再单位状态机，最后 AI）。

## 不做什么（当前）

- 不做联机对战、不做 UGC 编辑器对外发布、不做 4K 高配专用画面。
- 不在 `Game/` 里加新玩法代码（迁移期后 `Game/` 只减不增）。
- 不在玩法代码里写平台判断、不复制引擎层能力。
